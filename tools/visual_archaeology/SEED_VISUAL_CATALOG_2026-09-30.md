## V. Recommended family model

Do not give every file a flat independent label. Store:

- `family_id` — conceptual visual family;
- `variant_id` — member/parameter/layout variant;
- `duplicate_of` — exact or near-exact visual duplicate;
- `source_role` — notebook / plot / simulation / infographic / podcast art / external inspiration / UI capture;
- `historical_period` — independently evidenced date/range when available;
- `visible_features` — measurable/descriptive tags;
- `semantic_tags` — human/archive-supported meaning;
- `epistemic_status` — descriptive role, not theory truth;
- `archive_locations` — all known placements;
- `canonical_location` — only after dedupe/provenance choice.

This makes the classifier useful even when semantic certainty is low: it can reliably say “same family as p39 but different Up/Down configuration” or “split blue/red interface with diagonal ray” before it knows what that family means in the podcast grammar.
