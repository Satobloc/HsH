1. ᚼ / HAGALAZ TRANSFORM SOLVER
===============================================================================

INTRO
A recursive geometric transform intended to map one structured helix/frame state
into another and provide a common language for nested/superhelical constructions.

MATHEMATICAL STRUCTURE / PIECES
• Structured states S_i and transforms H_ji.
• Current candidate representation: oriented similarity
      H = (t, σ, Q),  u' = t + σQu,   Q ∈ SO(4), σ > 0.
• Composition, inversion, relative transforms.
• Six SO(4) rotation channels / parameter grid a–f in broader ᚼ work.
• Triangle/cycle composition:
      H20 H12 H01 = e.
• Exact two-edge → third-edge completion.
• Gauge/conjugacy treatment of closure residuals.
• Recursive application S1 → S2 → S3... for superhelices.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: formalize “apply the same kind of geometric operation again” when a
helix becomes a superhelix/higher-order structure.
Other: solver translation layer; compare geometric constructions; closure tests;
recursive-scale bookkeeping; potential common interface between otherwise
different SAT/H(s)H geometry engines.

USABILITY / CERTAINTY
• Algebra of the current similarity-transform candidate: usable.
• Triangle completion/residual mathematics: usable conditional on representation.
• Canonical identification with Nathan's original/intended ᚼ: NOT YET LOCKED.
• Six-channel/operator semantics: partly reconstructed.
• Treat current implementation as candidate formalization, not canonical definition.

SOLVER ECOLOGY / INTEGRATION
Highest-priority prospective unifier.
Can receive transforms extracted from other geometry solvers and compare them
without requiring those solvers to be identical.
Run 140–142 machinery supplies closure/comparison infrastructure.
Needs explicit mapping from Three-Spheres, Whirligig, UI/TX and hyperhelix outputs.

OUTWARD-FACING SPEC
“ᚼ is a recursive geometric-transform framework for representing how one
oriented, scaled and positioned geometric state becomes another. It supports
composition, inversion and closed-loop consistency tests, making it useful for
comparing nested geometric constructions. The current similarity-transform
implementation is a sandboxed candidate formalization rather than a claim that
all participating solvers are equivalent.”

2. DOUBLE-ROTATION / TWO-RATE RECURRENCE SOLVER
===============================================================================

INTRO
Recovers the two rotational rates underlying a sampled 4D double-rotation orbit.

MATHEMATICAL STRUCTURE / PIECES
• Two planar frequencies ω, ν.
• SO(4)-type double rotation / two orthogonal rotation planes.
• Sample sequence obeying an order-4 palindromic recurrence.
• Characteristic roots:
      e^(±iωτ), e^(±iντ).
• Recurrence coefficients → cosine roots:
      x = cos(ωτ), y = cos(ντ).
• Exact discriminant:
      Δq = 4 sin²[(ω+ν)τ/2] sin²[(ω−ν)τ/2].
• Block-Hankel/TLS numerical recovery.
• Lag/decimation τ = L dt as explicit conditioning variable.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: determine whether two hidden rotational rates can be reconstructed
from sampled geometric trajectories.
Other: chirality/rotation diagnostics; parameter recovery; benchmark for
solver identifiability; possible input to ᚼ relative-transform reconstruction.

USABILITY / CERTAINTY
• Exact recurrence mathematics: strong.
• Lag-conditioned discriminant: analytic.
• Numerical recovery: working on tested easy-gap benchmark.
• Adjacent sampling can be catastrophically ill-conditioned.
• Moderate decimation produced <1% median gap error in current easy-gap test.
• Small-gap resolution boundary still being measured.

SOLVER ECOLOGY / INTEGRATION
Provides parameter extraction rather than complete geometry generation.
Natural upstream feeder to ᚼ and rotational-state comparison.
Needs fixed, answer-blind lag-selection rule and standardized output schema.

OUTWARD-FACING SPEC
“This solver estimates two underlying rotational rates from sampled 4D
trajectory data. It uses an exact palindromic recurrence and explicitly accounts
for sampling-lag conditioning. It is intended for controlled reconstruction and
comparison of double-rotation geometries, with resolution limits reported rather
than assumed.”

4. FINITE-CORE / TANGENCY SOLVER
===============================================================================

INTRO
Calculates how finite-radius or finite-thickness structures meet near tangent
contact and how observable measures scale through the tangent-to-secant crossover.

MATHEMATICAL STRUCTURE / PIECES
• Local quadratic contact:
      z + αs + (Krel/2)s² = 0.
• Effective radius/thickness scales.
• Dimensionless crossover:
      Λ = |α| / √(K ρeff).
• Exact contact-span formulas.
• B³ volume, S² area and tilted-B² area branches.
• Universal tangency measure:
      M_p ∝ K^(-1/2) ε^(p+1/2).
• Finite-slab crossover function H(r).
• Unique fold and two-branch inverse reconstruction.
• Scale-free observables.
• Connected ↔ split contact-set transition.
• Vertex-centering and incidence reconstruction.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: replace idealized zero-thickness/tangent intersections with finite-core
geometry and determine which scaling laws survive.
Other: classify carrier dimensionality; inverse reconstruction; distinguish
incidence from thickness; generate publication-ready analytic discriminators.

USABILITY / CERTAINTY
• Large analytic portion now exact within declared local model.
• Multiple uniqueness/fold/inverse results derived.
• Dimensional typing repaired after earlier object-type mismatch.
• Some coefficients/branches tied specifically to Packet-002 definitions.
• Remains local quadratic finite-core geometry, not a universal interaction law.

SOLVER ECOLOGY / INTEGRATION
Currently the richest analytic discriminator family.
Can provide independent geometric observables against which larger solvers are
tested.
Not yet fully wired into ᚼ.
Excellent candidate for common benchmark/API because inputs and outputs are
low-dimensional and strongly typed.

OUTWARD-FACING SPEC
“The finite-core tangency solver models contact between finite-sized geometric
structures near tangency. It predicts contact spans, areas, volumes, topology
changes and inverse parameter reconstructions while explicitly distinguishing
tangent, crossover and secant regimes.”

6. FINITE-SLAB INVERSE / FOLD SOLVER
===============================================================================

INTRO
Reconstructs finite thickness versus carrier radius from contact observables and
identifies the exact two-branch ambiguity of that inverse problem.

MATHEMATICAL STRUCTURE / PIECES
• r = h/ε.
• Exact normalized observable:
      Y = H(r).
• Unique fold:
      r* ≈ 0.3686624731.
• Maximum:
      H* ≈ 1.6984077447.
• Intrinsic fold polynomial:
      Q(r)=2r⁵+10r⁴+5r³−15r²+45r−15.
• Scale-free observable:
      C = M4/(K³ℓ⁷).
• Exact ceiling:
      C* ≈ 0.00117280824.
• Below ceiling: two inverse branches.
• At ceiling: coalescence.
• Above ceiling: no solution within model.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: determine whether finite-thickness measurements uniquely reconstruct
the underlying geometric decomposition.
Other: identifiability analysis; conditioning; model-consistency test; curvature
floor; thin-slab and thin-carrier asymptotics.

USABILITY / CERTAINTY
Analytically mature within its stated finite-slab model.
Branch ambiguity is intrinsic, not treated as numerical failure.
Needs consolidation into a single clean implementation/API.

SOLVER ECOLOGY / INTEGRATION
Subsolver of finite-core tangency but publication-worthy independently.
Provides a model-consistency discriminator other solvers can query.

OUTWARD-FACING SPEC
“This inverse solver determines which finite-core geometries are compatible
with a measured contact span and volume. It explicitly reports the model's
two-solution region, unique fold point and impossible region rather than
forcing a single reconstruction.”

7. EXACT QUADRATIC CROSSOVER / CONTACT-TOPOLOGY SOLVER
===============================================================================

INTRO
Tracks the exact transition from one connected contact region to two separated
contact regions as incidence departs from tangency.

MATHEMATICAL STRUCTURE / PIECES
• Symmetric support condition:
      |½Ks² + αs| ≤ ρ.
• Λ = |α|/√(Kρ).
• Exact normalized contact span:
      F(Λ)
      = [√(Λ²+2) − √((Λ²−2)_+)]/√2.
• Unique maximum:
      Λ = √2,
      F = √2.
• Same point is connected→split topology transition.
• Vertex:
      sv = −α/K.
• Threshold equivalence:
      |sv| = L0/2.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: make Packet-002's tangent/secant crossover geometrically explicit.
Other: infer incidence from contact position; topology-based classification;
generate exact benchmark cases for numerical contact solvers.

USABILITY / CERTAINTY
Exact for the declared quadratic symmetric-support model.
Cubic/higher-order contact terms can break the reflection symmetry.

SOLVER ECOLOGY / INTEGRATION
Natural local-contact primitive for finite-core solver.
Could become a common low-level library function used by several geometry engines.

OUTWARD-FACING SPEC
“This solver computes the exact size and topology of a quadratic finite contact
region. It identifies the unique point where total contact is maximal and where
one connected contact interval splits into two.”

8. TORUS / WINDING / FRAME-HISTORY SOLVER
===============================================================================

INTRO
Separates torus-path closure, intrinsic torus holonomy and embedded 4D frame
history so they cannot be accidentally treated as the same quantity.

MATHEMATICAL STRUCTURE / PIECES
• Product torus:
      ds² = a²dp² + b²dq².
• Closed winding classes (m,n).
• Intrinsic Levi-Civita connection: flat.
• For closed integer winding:
      Hol^LC = I.
• Embedded SO(4) frame history.
• Rotation generators in orthogonal planes.
• Path-ordered exponential:
      Qγ = P exp ∫A.
• Commuting and noncommuting generator cases.
• Magnus-expansion commutator structure.
• Rational/irrational winding and closure structure.

ORIGINAL PURPOSE / OTHER PURPOSES
Original: formalize toroidal/null/winding constructions and determine what
“holonomy” could legitimately mean in them.
Other: prevent false inference from path closure; distinguish intrinsic from
extrinsic/frame effects; study ordered rotational history.

USABILITY / CERTAINTY
Key distinctions are established and usable.
Intrinsic product-torus LC holonomy is trivial for the closed paths studied.
Noncommuting frame-history machinery is mathematically available but its exact
role in canonical H(s)H remains under development.

SOLVER ECOLOGY / INTEGRATION
Important semantic/type-checking solver.
Potential feeder into ᚼ because both manipulate SO(4) frame histories.
Must preserve:
      path closure ≠ intrinsic LC holonomy ≠ frame/bundle history.

OUTWARD-FACING SPEC
“This solver analyzes paths on and around toroidal geometries while keeping
three different notions separate: whether a path closes, what intrinsic parallel
transport does, and how an embedded 4D frame rotates along the path.”

HISTORICAL USES — CONDENSED
===============================================================================

The solver family, its predecessors and associated hand calculations have been
used or attempted for:

• reconstructing SAT angular/torsional and later H(s)H hyperhelical geometry;
• exploring worldline → worldtube and recursive-coiling representations;
• modeling particle-like, photon-like and neutrino-like geometric modes;
• exploring precession/clipping and rotated-out-of-readout constructions;
• examining candidate characteristic angular values including ~0.246 rad;
• pulsar-glitch / “Quantized Holonomy Transition” model attempts;
• He-3 / “Holotype Atom” geometric constructions;
• shell, sphere and carrier-intersection studies;
• toroidal winding, chirality, flip/flicker and reconnection constructions;
• emergent-metric / metric-induction attempts;
• finite-core corrections to idealized intersections;
• closure, recurrence, rotational-rate and holonomy reconstruction;
• searching for scale-invariant or dimensionless discriminators;
• determining whether apparently different geometric representations give the
  same, different, degenerate or presently incomparable outputs.

Some historical calculations were judged promising or internally consistent at
the time; some were subsequently downgraded, corrected or retyped. External
comparisons have identified structural similarities in selected mathematical
motifs, but no blanket equivalence between SAT/H(s)H and external theories—or
among the internal solvers themselves—is currently assumed.

giving them a sufficiently precise common interface to exchange geometric data.

# ---------- A. Recurrence resolution sweep ----------
rng=np.random.default_rng(260927)
dt=0.025
t=np.arange(-2,2+1e-12,dt)
omega=1.1
gaps=np.array([0.10,0.03,0.01,0.003])
strides=np.arange(1,31)

def signal(nu, noise=1e-4):
    # four-coordinate two-plane double rotation, fixed amplitudes
    X=np.c_[1.2*np.cos(omega*t),1.2*np.sin(omega*t),
            .65*np.cos(nu*t),.65*np.sin(nu*t)]
    return X+rng.normal(scale=noise,size=X.shape)

def estimate_gap(X,L):
    # Fit shared palindromic recurrence:
    # c[n+4L] - s1 c[n+3L] + s2 c[n+2L] - s1 c[n+L] + c[n]=0
    # => s1*(c3+c1) - s2*c2 = c4+c0
    rows=[]; rhs=[]
    N=len(X)-4*L
    if N<8: return np.nan
    for n in range(N):
        for j in range(4):
            rows.append([X[n+3*L,j]+X[n+L,j], -X[n+2*L,j]])
            rhs.append(X[n+4*L,j]+X[n,j])
    A=np.asarray(rows); b=np.asarray(rhs)
    s1,s2=np.linalg.lstsq(A,b,rcond=None)[0]
    # q^2 - s1/2 q + (s2-2)/4 = 0
    roots=np.roots([1,-s1/2,(s2-2)/4])
    if np.max(np.abs(np.imag(roots)))>1e-6: return np.nan
    q=np.clip(np.real(roots),-1,1)
    rates=np.sort(np.arccos(q)/(L*dt))
    return abs(rates[1]-rates[0])

trials=120
med=np.full((len(gaps),len(strides)),np.nan)
for gi,g in enumerate(gaps):
    nu=omega-g
    for li,L in enumerate(strides):
        errs=[]
        for _ in range(trials):
            est=estimate_gap(signal(nu),L)
            if np.isfinite(est):
                errs.append(abs(est-g)/g)
        if errs: med[gi,li]=np.median(errs)

# Answer-blind rule chosen analytically for the smallest possible expected gap range:
# maximize the minimum exact discriminant over target gaps, with >=40 recurrence windows.
validL=[L for L in strides if len(t)-4*L>=40]
def discr(g,L):
    nu=omega-g; tau=L*dt
    return 4*np.sin((omega+nu)*tau/2)**2*np.sin(g*tau/2)**2
scores=[min(discr(g,L) for g in gaps) for L in validL]
Lstar=validL[int(np.argmax(scores))]

fig,ax=plt.subplots(figsize=(8,5))
for gi,g in enumerate(gaps):
    ax.plot(strides,med[gi],marker='o',ms=3,label=f"Δω={g:g}")
ax.axvline(Lstar,ls='--',label=f"answer-blind L*={Lstar}")
ax.set_yscale("log"); ax.set_xlabel("stride L"); ax.set_ylabel("median relative gap error")
ax.set_title("Two-rate recurrence: resolution vs sampling stride")
ax.legend()
fig.tight_layout()
