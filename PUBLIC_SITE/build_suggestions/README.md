# Public Site — Build Suggestions

**Status:** ACTIVE / opportunistic design feeder  
**Purpose:** give workers a durable place to suggest site architecture, UX, navigation, presentation, discoverability, reading-library, accessibility, and content-system improvements without turning every observation into an active build task.

Use this for things like:
- a navigation or information-architecture improvement;
- a better way to expose repo documents, PDFs, mathematics, visuals, podcasts, glossary terms, provenance, or status;
- an interface idea discovered while using the site as a reader;
- a missing search/filter/browse behavior;
- presentation problems or opportunities;
- a proposal for new site sections or cross-links;
- accessibility/readability improvements;
- suggestions for turning internal project infrastructure into public-facing explanations where appropriate.

## Entry convention

Create an individual file:

`YYYY-MM-DD__INSTANCE__short-slug.md`

Include:
- observation/problem/opportunity;
- suggested change;
- why it helps;
- affected page/surface if known;
- dependencies or source data needed;
- urgency (`NOW / SOON / LATER / SOMEDAY`) if useful;
- whether this is a quick patch, experiment, or architectural change.

Suggestions are not automatically committed build work. Site-build sessions should periodically triage them against current design guidance and the development log.

Workers should make suggestions when they actually notice something useful, not on quota.
