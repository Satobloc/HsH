## 4. Cross-reading: two firsts are not enough unless event types and coverage are explicit

The existing Aldus Blockwave two-firsts packet already established that different systems record different events:

- A's first currently found Git ingestion: 2026-09-04, commit `e3059ea...`; NotebookLM collection event: 2025-09-14.
- B and C were co-ingested by the same 2026-10-08 Git commit `6e4415f...`; NotebookLM collection events: 2025-10-23 and 2025-10-25.
- The collection dates do not date equation creation, and the Git import date does not establish first public exposure.
- The structural B-to-C relationship may be discussed separately from a dated temporal direction. First public T0 remains unresolved for those equation spans.

That result should be generalized without replacing the original two-firsts distinction.

### Proposed temporal-evidence record

A timestamp must be stored with its subject and event semantics, not as an untyped scalar:

```text
TemporalEvidence {
  subject_kind,
  subject_id,
  event_kind,
  event_time,
  clock_domain,
  stated_precision,
  source_locator,
  observed_at,
  observation_method,
  coverage_scope,
  epistemic_status,
  attempt_id_or_UNAVAILABLE
}
```

Candidate event kinds include:

- SOURCE_MESSAGE_CREATED
- SOURCE_FILE_CREATED
- REPOSITORY_INGESTED
- PUBLICLY_RELEASED
- COLLECTION_INDEXED
- RETRIEVED_BY_AUDIT
- RUN_SCHEDULED
- RUN_STARTED
- RUN_COMPLETED
- RESULT_PERSISTED
- TASK_METADATA_UPDATED
- SCHEDULER_SNAPSHOT_OBSERVED
- MESSAGE_DELIVERED
- MESSAGE_INCLUDED_IN_CONTEXT

The record also needs a snapshot/observation identifier. `observed_at` is when an audit retrieved a state; it is not the provider-side time at which that state was generated. Stated timestamp precision is not a claim about clock accuracy.

### Scoped first-event rule

A chronology claim should be scoped by:

- subject/feature;
- event kind;
- verified source corpus;
- search window and coverage;
- clock domain and comparability;
- source authority and date confidence.

The earliest verified event within a bounded corpus is not automatically the true global first. If earlier coverage is incomplete, use `EARLIEST_VERIFIED_CANDIDATE` or `PUBLIC_T0_UNRESOLVED`, not an unqualified `FIRST_PUBLIC`. A NotebookLM collection event, Git ingestion event, source-message creation event, public release event, and audit retrieval event are different types.

A total chronological ordering is not justified when event timestamps belong to uncalibrated clock domains or have unresolved uncertainty. The safe relation is a partial order over comparable, provenance-backed event records; otherwise return `TEMPORAL_ORDER_UNRESOLVED`.

This is a proposed typed schema and proof target, not an implemented standard or a Lean theorem. A Lean-ready formalization needs exact definitions for event kinds, subject identity, clock-domain comparability, coverage completeness, and the candidate set. No data-free fixture or physical calculation was run.
