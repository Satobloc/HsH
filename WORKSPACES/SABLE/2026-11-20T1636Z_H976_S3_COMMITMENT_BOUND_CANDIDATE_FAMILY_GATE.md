## 3. New integration: Commitment-Bound Candidate Manifest (CBCM) v0.1

The new contribution is a small binding layer inside the existing seven-layer source-to-observable chain, not a replacement for it. Ariadne's existing chain already separates Claim, Source, Acquisition, Representation, Model, Readout and Decision. CBCM strengthens the **Model** layer so a candidate-family hash cannot be frozen independently of the source commitments and geometry maps that define what the candidate is.

### Required binding

Each confirmatory model-family record must bind:

- `source_commitment_map_id` and immutable `source_commitment_map_hash`;
- source proposition IDs, source roles, dates, locators, content hashes, authority and `claim_currentness`;
- `commitment_class` and `commitment_strength` separately from `implementation_status`;
- `geometry_map_stack_id` and hash, including domain/codomain, operation class, composition order, fibers/kernel, inverse/section, invariants, regularity and any error bound;
- candidate-family ID/version/hash and freeze timestamp;
- complete eligible candidate IDs, shared parameters, nuisance parameters, candidate-specific parameters and comparator version;
- `candidate_variant_class` and the witness required by that class;
- observable/readout ID, measurement-operator version, units and uncertainty/covariance reference;
- holdout-exposure-ledger ID and the rule for invalidating confirmatory status after feedback.

### Variant classes

| `candidate_variant_class` | Admission rule |
|---|---|
| `SOURCE_COMPLIANT_BASELINE` | Retains every applicable source-committed premise and inherited constraint; unresolved implementation details remain explicit. |
| `CONTROLLED_APPROXIMATION` | May reduce a committed structure only with an explicit projection/retraction and either exact readout factorization or a calibrated, unit-consistent error bound fixed before holdout access. |
| `OPTIONAL_EXTENSION` | Requires a separate source or data rationale, explicit map/composition, new parameter accounting and a predeclared observable that can distinguish it. Fit improvement alone is insufficient. |
| `STANDARD_COMPARATOR` | Uses the same acquisition units, measurement operator, calibration policy, nuisance flexibility, uncertainty treatment and decision metric. |
| `UNRESOLVED_NOT_ADMISSIBLE` | May remain in exploratory notes but cannot enter the confirmatory candidate family. |

`commitment_class`, `claim_currentness`, `implementation_status`, `candidate_variant_class`, and `empirical_status` are independent fields. A qualitative commitment is not a numerical parameter estimate; an unresolved implementation is not a source withdrawal; a successful approximation is not proof that the underlying physical structure is absent.

### Approximation witness

A `CONTROLLED_APPROXIMATION` record must identify:

1. the source geometry being reduced;
2. the projection/retraction map, domain, codomain and composition order;
3. the target observable and its metric/units;
4. whether the readout is exactly constant on projection fibers;
5. if only approximate, the calibrated error bound, covariance/uncertainty provenance and tolerance rule;
6. the calibration data and the predeclared holdout rule.

The exact fiber-factorization condition and the resolution-limited bound are reused from existing formal work. No numerical epsilon, Lipschitz constant, resolution, tolerance or physical fixture is invented.

### Family-hash and exposure rule

The family hash binds the source-commitment-map hash, geometry-map-stack hashes, complete candidate list, parameter roles/ranges, comparator, observable, decision rule and holdout policy. No confirmatory holdout is opened before those inputs are frozen. If holdout feedback influences candidate generation or changes the eligible family, the family version/hash changes and the prior holdout becomes development data unless a separately specified adaptive-holdout guarantee applies. A final-list multiplicity correction alone does not repair an adaptively changing family.

## 4. Gate composition and dependency order

The existing controls are composed as a dependency graph rather than duplicated as parallel pass/fail badges:

1. **Source authority/currentness** -> immutable SourceCommitmentMap.
2. **Geometry fidelity and typed map stack** -> explicit representation and composition maps.
3. **CBCM / CandidateFamilyManifest** -> requires both the source map and geometry map stack.
4. **Structural identifiability** -> evaluated for the declared target and observable, not inferred from parameter count alone.
5. **Resolution stability** -> requires declared readout/target metrics, instrument resolution and uncertainty/covariance.
6. **Acquisition independence** -> binds attempted acquisitions, observed units/channels, detector/instrument/calibration lineage and dependence structure.
7. **Holdout freeze** -> requires frozen family, resolution assessment, acquisition-unit map, calibration policy and exposure ledger.
8. **Prediction lock** -> prediction and falsification rule frozen before confirmatory holdout access.
9. **Independent validation** -> only after the identified real system, versioned raw data, units, uncertainty and independent acquisition-level holdout exist.

The acquisition and geometry branches may be developed in parallel, but neither can be silently skipped at holdout admission. Factory Floor's precise-plot and hostile geometric-fidelity review is an orthogonal admission gate; it does not substitute for source authority, mathematical verification or empirical validation.
