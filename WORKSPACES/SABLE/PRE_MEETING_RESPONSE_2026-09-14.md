## Automation/productivity lessons

Measure useful durable state change per cycle, not number of runs. Useful dimensions:

1. meaningful state change;
2. verification/QA performed;
3. reusable artifact produced;
4. continuity/handoff quality;
5. duplication/rework;
6. blocked/no-op cost;
7. useful training/exploration yield.

Blocked workers should become condition-triggered, slow-frequency, or move into approved alternate/exploration work rather than rediscovering the same unchanged gate hourly.

The Solve-for episode is a useful failure exemplar: extraction/tagging machinery can succeed while contextual classification fails. Successful retrieval and correct understanding of what kind of source one is looking at must be treated as separate competencies.
