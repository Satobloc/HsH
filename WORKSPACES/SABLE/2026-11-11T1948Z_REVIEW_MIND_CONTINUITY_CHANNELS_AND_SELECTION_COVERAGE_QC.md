## 6. Review-MIND result: refine six channels into nine typed evidence channels

Kestrel's six-channel model is a useful orientation, but its fourth channel combines a run-level conversation pointer with actual message exposure. Those are different evidence types. The operational schema should distinguish:

1. **Role/intent provenance** — the source and scope of a worker remit.
2. **Nominal selection** — the deterministic ring label selected by ((h,s)).
3. **Execution lease** — task ID, run ID, scheduled/start/completion timestamps and status.
4. **Configured task container** — the conversation ID configured on the recurring task.
5. **Run-level conversation reference** — nullable `chat_ref` or equivalent runtime pointer.
6. **Message-level exposure/delivery** — message IDs and provenance showing what was actually present to, delivered to, or consumed by a run.
7. **Durable work state** — repository, path, commit, blob and exact readback.
8. **Capability/access snapshot** — tools and permissions available at the run, distinct from tools actually invoked.
9. **Authenticated subject/instance identity** — a separately evidenced identity binding, not inferred from a role label or task container.

The channels need typed maps, not a flat analogy:

- `select : SlotEvent → WorkerLabel`
- `lease : RunID → (TaskID, RunMetadata)`
- `taskOfRun : RunID → TaskID`
- `configured : TaskID → Option ConfiguredConversationID`
- `runRef : RunID → Option RunConversationID`
- `exposure : RunID × MessageID → ExposureState`
- `produces : RunID → Set ArtifactRef`
- `capability : RunID → CapabilitySnapshot`
- `authenticatedAs : RunID → Option InstanceID`
- `roleSource : WorkerLabel → SourceRef`

The composition `configured ∘ taskOfRun` yields the configured container for a run. It does **not** yield the run-level reference, message-level exposure, or authenticated instance. Those require separate evidence edges.

Consequences:

- Same configured conversation ID does not prove that a particular predecessor message was in the successor's context.
- Same run-level conversation reference does not prove which messages were exposed or consumed.
- Different worker labels do not prove different instances or independent reasoning.
- Different report references do not prove independent source acquisition.
- Tool availability does not prove tool use.
- A repository artifact/commit does not authenticate the worker that produced it.

Define actual continuity for a specific message only when a verified predecessor-to-successor exposure edge exists, with source/message identity and acquisition provenance. Missing exposure evidence is UNKNOWN, not ABSENT and not proof of continuity.

Represent independence as a vector of separately evidenced dimensions—subject identity, execution identity, primary-source lineage, context exposure, model/version and evaluator—not a single Boolean. Each dimension should admit YES / NO / UNKNOWN with a source reference. Reuse VEY-042's selection-coverage states for candidate-source coverage; do not collapse authority, provenance, selection, exposure, comprehension, uptake, action, execution and outcome.

Randomize role labels independently of those conditions.
