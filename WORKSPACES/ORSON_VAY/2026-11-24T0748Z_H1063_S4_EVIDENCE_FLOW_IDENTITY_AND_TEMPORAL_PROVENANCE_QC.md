## 4. External methodological comparator

A bounded SciSpace discovery surfaced this as a candidate, but the SciSpace fetch action did not retrieve it. A public web search then located the AAAI-hosted PDF, which was read in full. The comparator selection was relevance-based, not a randomized peer-review draw. The source is:

Samuel Westby and Christoph Riedl, “Collective Intelligence in Human-AI Teams: A Bayesian Theory of Mind Approach,” *Proceedings of the 37th AAAI Conference on Artificial Intelligence* (2023), DOI [10.1609/aaai.v37i5.25755](https://doi.org/10.1609/aaai.v37i5.25755), [arXiv:2208.11660](https://arxiv.org/abs/2208.11660), [full paper](https://ojs.aaai.org/index.php/AAAI/article/download/25755/25527).

The paper reports an IRB-approved experiment with 145 people in 29 **human-only** teams of five, assigned to communication topologies and solving a Hidden Profile task through a five-minute chat. Bayesian agents then shadow the human participants using the observed human messages. The paper's AI-agent intervention results are counterfactual simulations, not a deployed live LLM-team experiment. The agents are Bayesian generative models, not ChatGPT or other LLMs.

The model's useful methodological structure is explicit:

- Each shadow agent has an Ego model and an Alter model for each network neighbor.
- Ego models update from the participant's own information and outgoing messages.
- Alter models update from incoming messages from the corresponding teammate.
- Message order drives sequential belief updates.
- The paper's communication measure \(\alpha_C\) is based on the sender's expected surprise relative to the sender's own Alter model of the recipient. It is not a direct observation of the recipient's actual retrieval, comprehension, uptake, or decision use.

The public [code repository](https://github.com/riedlc/HumanAITeamsAndCI), [README](https://github.com/riedlc/HumanAITeamsAndCI/blob/main/README.md), [`scripts/simulation.py`](https://github.com/riedlc/HumanAITeamsAndCI/blob/main/scripts/simulation.py), and [`data/messages.json`](https://github.com/riedlc/HumanAITeamsAndCI/blob/main/data/messages.json) were inspected. In `simulation.py`, the simulator iterates through the stored ordered message sequence, reads the speaker and listener list, and updates each listener's model using the five coded evidence values. The extra numeric field in each message record is not used by that update loop; its meaning was not inferred. Only the schema and a redacted structural record were inspected; there was no participant-level or outcome reanalysis.

**Comparator limit:** this is evidence about a Bayesian model fitted to human-human communication and simulated interventions. It is not direct evidence about LLM cognition, LLM-to-LLM group interaction, or AI consciousness. It is useful as a concrete example of event order, recipient-specific observation, and nested representational models.

### 5.1 What is proved

The theorem `no_observation_only_decoder_of_ambiguous_models` is logically correct as a conditional statement: if two distinct models share one observation, no total observation-only decoder can recover both models exactly. It is a narrow non-injectivity / no-left-inverse result.

It does **not** establish that the historical source's undefined “isometric” relation is non-injective, that there are infinitely many compatible interpretations, or that any physical or cognitive observation map has been identified. It does not supply the missing source-to-formalization translation.

`VerifiedRouteFunctional` is an explicit additional condition, not a result derived from route metadata. The theorem that verified bindings agree is conditional on that functionality assumption.

### 5.2 Route-identity modeling gap

`RouteObservation` records worker label, automation ID, and nominal hour, but does not explicitly record slot phase or schedule revision. If the automation ID uniquely fixes the phase, that mapping is external to the formalized record and is not stated as an invariant.

`AgentIdentity` includes a run ID. If one nominal route can correspond to multiple legitimate execution attempts or overlapping runs, a route-only functionality condition may be too strong. The resolver should either include an explicit run/attempt key in the route or be indexed by both route and evidence key. The current theorem is useful precisely because it exposes the need for that additional identity evidence.

### 5.3 Evidence-flow identity and scope gaps

`OrsonEvidenceFlow.lean` uses finite sets of `EvidenceItem` and `DisclosureEvent`, but it does not define a `ValidEvidenceFlow` predicate enforcing unique `itemId` and `eventId` values or referential integrity. A `Finset` prevents duplicate *whole structures*; it does not guarantee that semantic IDs are unique when other fields differ.

`itemPresentAt` matches by `itemId` alone. Two structurally different item records with the same `itemId` but different source-root sets can therefore be treated as the same item. Distinct event structures can likewise carry the same `eventId`. The model also lacks an explicit task/session/episode key, so a same-contributor pair can span unrelated task contexts unless the surrounding flow is already guaranteed to be single-task.

The adjacent `OrsonCRTCGroupProjection.lean` does enforce event-ID uniqueness in `ValidEventSet`, so the two modules currently have different identity guarantees. That difference should be reconciled before their results are composed.

### 5.4 Temporal and uptake gaps

`InteractionEvent` in `OrsonCRTCGroupProjection.lean` contains a timestamp, but the current `memberEvents` and `subgroupEvents` projections do not use it. The current theorem `subgroup_member_projection_composes_iff` is a valid static group-scope composition result under its explicit containment condition. It does not establish temporal co-availability or time-window composition.

`usedBy` and `incorporatedIntoDecision` are event properties, not separate retrieval, uptake, decision-use, decision, and outcome events. The schema therefore does not yet distinguish:

- an item being retained;
- a recipient being able to access it;
- the item being present in the same active context as another item;
- actual retrieval or reading;
- correct comprehension;
- explicit use in a decision;
- the decision itself;
- an independently assessed outcome.

Endpoint presence or recipient membership must not be promoted to temporal co-availability, comprehension, decision uptake, or correctness.

## 7. Proposed typed event chain and falsification design

**Proposal only. Not implemented, not Lean-verified, and not a P1 protocol amendment.**

A source-faithful event model should keep distinct identities for:

1. `EvidenceItem`: immutable item ID, source-root IDs, source version/hash, epistemic role, and authority/validity metadata.
2. `DisclosureEvent`: event ID, item ID, sender, recipient set, channel, task/session/run key, ordered event time, and payload/source reference.
3. `VisibilityInterval`: recipient-specific start/end or context-window membership, backed by an actual trace rather than inferred from storage.
4. `RetrievalEvent`: recipient, item ID, retrieval/read event ID, and time.
5. `UptakeAssessment`: recipient, item ID, operational comprehension criterion, evaluator/version, and evidence.
6. `DecisionUse`: decision ID, item ID, recipient, time, and an explicit incorporation relation.
7. `Decision`: decision identity, task/session, output, and time.
8. `Outcome`: outcome identity, decision reference, external criterion, assessor/version, and provenance.

Required invariants include unique semantic IDs, valid cross-references, explicit task/session scope, preserved source lineage, ordered event semantics, and declared evaluator/criterion versions.

A temporal projection must identify the events visible to a particular recipient at a particular time and under a declared context-window rule. Pair co-availability requires both items' visibility intervals to overlap **and** both to fit within the same active context. Availability is not retrieval; retrieval is not uptake; uptake is not decision use; decision use is not correctness.

The existing static subgroup-to-member composition theorem can serve as a starting point, but a temporal composition theorem requires explicit interval/window semantics and a proof that every event retained by the direct projection survives each intermediate projection. No such theorem is claimed here.

### Future disconfirmation sketch

After explicit authorization and a consent/privacy review, a bounded study could vary source lineage (independent versus shared) and disclosure timing (simultaneous versus staggered) while holding claim content and message volume constant. Human teams and LLM teams should be separate strata, not silently pooled. The primary outcome would compare group confidence/consensus with independently adjudicated correctness while recording unique source roots, actual visibility, retrieval, uptake, and decision-use events.

The hypothesis that apparent consensus overstates independent evidence would be weakened if shared lineage produced no calibration penalty after actual exposure and unique source roots were controlled, or if consensus remained calibrated under deliberately shared-source conditions. Thresholds, sample size, evaluator reliability, and analysis would have to be specified before any trial. This is a future design sketch only; no subjects, models, APIs, or datasets were used in this run.
