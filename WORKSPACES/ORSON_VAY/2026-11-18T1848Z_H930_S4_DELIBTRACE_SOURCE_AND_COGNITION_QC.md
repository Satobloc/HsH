## 3. Source-code correction: four perspectives, eight initial agent outputs

The paper describes four evidence perspectives. The public code makes the actual initial population explicit:

- `perspective.py` constructs four GPT-5-generated fact subsets.
- `discussion.py` calls the initial-response function twice per subset, once with YES and once with NO, producing eight initial agent outputs.
- `random_index_*.json` is generated from a fixed Python seed (20260601) to permute the eight outputs before topology assignment.
- The full, binary-tree, and line graphs operate over those eight outputs. The code's tree/line neighbor lists are reciprocal.
- Each output is generated by the same selected model family for a condition; there are four evidence profiles duplicated across opposing stance prompts, not eight independent evidence profiles or independently sampled model identities.

This pairing is a controlled stance-initialization feature, not a defect by itself. But the effective population structure is **4 evidence profiles x 2 prompted stances = 8 outputs**. Treating the eight as independent evidence profiles would overstate diversity. The pairing should be carried in any analysis of topology, stance entropy, per-agent retention, or dependence.

The discussion prompt explicitly asks each initial response to mention all assigned facts. Subsequent calls receive the agent's previous text and neighboring agents' previous texts. This is prompt-mediated simulation of agent persistence, not a persistent independent-agent architecture.

## 4. Metric and construct QC

The paper uses:
- system-level Jaccard retention between the union of initial evidence sets and the union of facts extracted from outputs;
- mean agent-level Jaccard between each agent's assigned facts and its extracted output facts;
- binary stance entropy over the agent population.

The system-union measure asks whether a fact is recoverable anywhere. It does not by itself measure uptake by a particular agent, transfer to an initially non-holder, or common-ground convergence. Agent-level retention partially addresses this, but no distinct transfer/path metric is reported.

The fixed-fact evaluator only selects IDs from the supplied fact universe. It therefore does not independently count new factual claims outside that universe. Retention and unsupported-addition/factuality should be separate measures.

The reported union/intersection reconstruction results show that system-wide recoverability and shared common ground are different quantities. A group may retain a fact somewhere without all members sharing it. Conversely, consensus/entropy alone does not reveal whether minority evidence was retained, lost, or merely omitted from a final response.

## 5. Evaluator dependence and human validation

GPT-5 is used for fact extraction, refinement, criticality labels, perspective generation, post-discussion fact extraction, stance evaluation, and additional evaluation. This is a common evaluator/generator dependency across conditions. It does not invalidate the study, but it limits evaluator independence and makes condition-stratified validation important.

The paper reports three human annotators and agreement figures:
- criticality: exact-match 0.767, agreement 0.541;
- evidence consistency: exact-match 0.900, agreement 0.789;
- stance: exact-match 0.980, agreement 0.947.

Criticality agreement is notably weaker than stance agreement. The PDF's Appendix C.4 "Annotation Results" heading has no visible table/content; sample sizes, agreement statistic details, and annotation distribution are not recoverable from that section in the inspected version. These are reporting gaps, not evidence that the validation was fabricated.

## 6. Reproducibility boundary

The official GitHub repository at commit `afce35955c488570c7e46e7af2bec3faca85f15e` (2026-05-19) contains five source files and nine prompt files. The 38-byte README only says it is the official repository.

The public source does not include the generated facts, perspective assignments, discussion outputs, evaluation results, or a separate metric-aggregation script. Thus the public repository is a partial implementation, not a turnkey reproduction package.

The code uses model aliases (gpt-4.1, gemini-3-flash-preview, qwen3.5-flash), temperature 1.2 for discussion, and no API generation seed. The fixed seed controls the eight-output order, not model sampling. Repeated-generation seed replication is not documented in the inspected code. Exact provider/model snapshots, prompts, raw output traces, failures, and metric aggregation need a versioned release for reproducibility.

## 7. Methodological crosswalk for cognition research

Carry separate typed records for:
1. source evidence and atomic-fact ancestry;
2. initial evidence profile and stance pair;
3. randomized exposure/visibility and actual message path;
4. per-agent retention of originally assigned evidence;
5. uptake of facts by initially non-holders;
6. system recoverability and common-ground intersection;
7. new/unsupported factual additions;
8. criticality-weighted retention;
9. stance entropy and minority-position persistence;
10. downstream decision accuracy, confidence, and uncertainty.

For a causal peer-exposure study, randomize visibility or routing while matching initial evidence/stance; retain a no-message self-revision control; record multiple sampling seeds, model/version, prompts, agent order, and every exposure event; use independent, condition-stratified annotation with sample sizes and agreement metrics; and preregister the estimand and selection rules.

This is a prospective design recommendation only. No experiment or API call was made.
