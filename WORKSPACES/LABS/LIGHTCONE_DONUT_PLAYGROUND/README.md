The purpose is **not** to be careful enough to be correct on first pass. The purpose is to make many small objects that can be touched, bent, rendered, broken, crossed, and recombined.

The governing attitude for this lab:

> Build playful models first. Label them later. Kill what fails. Keep what sparks.

## First playground synthesis

### Object 1 — the covering-space lantern

Take a compact 3-torus. Do not draw the torus. Instead unwrap it into an infinite crystal of image-cells.

Put an observer in one cell. Emit the observer's past light cone as a growing spherical shell through the covering space.

When the shell reaches adjacent copies, the sky stops being simply one sky. It becomes a **lantern of re-entries**:

- the same physical source may appear along multiple image paths;
- the same last-scattering patch may arrive from multiple directions;
- the same object may have several apparent ages;
- apparent angular separation is no longer the same thing as native topological relation;
- the first detectable event is not “seeing a donut” but seeing a repeated relation.

Toy variable names:

- `Lx, Ly, Lz` — compact lengths;
- `eta` — conformal lookback radius;
- `n = (nx, ny, nz)` — image-cell vector;
- `d_n = |x_source + nL - x_observer|` — covering-space light path;
- `age_n = eta_now - d_n` — apparent source age by path;
- `multiplicity(source) = count(n such that d_n <= eta_now)`.

Play move: animate `eta` and let duplicated sources bloom when the shell first hits image cells.

### Object 2 — the matched-circle music box

Classic compact-topology CMB simulations look for matched circles. Make that more playful:

Each pair of matched circles is treated as a **musical interval** on the sky.

- Circle radius becomes pitch.
- Relative phase shift becomes rhythm offset.
- Orientation reversal becomes timbre flip.
- Translation-only torus gives repeating motifs.
- Screw/twisted identification gives rotated motifs.
- Klein-like identification gives mirror/inverted motifs.

This is not a physics claim. It is a perceptual workbench. The goal is to make duplicate topology audible/visible so it becomes easier to notice representation mistakes.

### Object 3 — the coil-let fog machine

Import from Coil-let lab: traveling packet on carrier.

Now put coil-let packets in compact topology. Let packets propagate not as isolated dots but as little phase-tagged coil states:

`packet = {position, carrier_id, phase, chirality, closure_score, coupling_channel}`

In a compact torus, each packet has image copies. But image copies may not be physically separate objects; they are alternate path-readouts of the same object.

Play question:

> What happens if packet closure is evaluated not only locally, but across image paths?

Toy rule to try:

`closure_score = min over image paths of phase mismatch after transport`

or

`registration happens when at least k image-path returns agree within epsilon`.

Wild interpretation to test visually: particle-like registration may be a local detector event fed by a globally compact phase return condition.

Kill condition: if this just smuggles target behavior by arbitrary thresholds, discard it.

### Object 4 — the Forest shortcut mirror

Import from Forest lab: information requires physical ancestry/path; ordinary projected locality and native worldtube adjacency may differ.

In a compact topology, a far-away object may be near by wraparound path. In a Forest-like locality layer, two points that look remote on one projection may be native-adjacent through a worldtube or topological return.

Build a toy map with two distance measures:

- `d_visual` — distance in the displayed cell;
- `d_native` — shortest compact/geodesic/topological path;
- `d_packet` — coupling distance for a chosen channel.

Then deliberately let them disagree.

Play question:

> What would an observer infer if light uses `d_visual`, gravity uses `d_native`, and packet registration uses `d_packet`?

Possible outputs:

- apparent missing mass;
- duplicate-source correlations;
- anisotropic propagation lags;
- nonlocal-looking ancestry that is local in another channel;
- CMB-style matched structures that do not line up with matter clustering.

This is a playground for coupling mismatches, not a claim that H(s)H does this.

### Object 5 — handle rain

Import from the uploaded topology conversation and the labs context: topology change, reconnection, handle addition, genus jumps.

Make a toy where compact space is fixed, but packets or worldtube surfaces can add handles when crossing conditions fire.

Potential trigger:

`crossing + phase resonance + low relative transport mismatch -> handle birth`

Visual name: **handle rain**.

If fixed compact topology is the stage, handle rain is local morphology/topology of fields or worldtube sheets, not the universe changing its base topology.

Play question:

> Can a fixed toroidal universe host local handle-rain events that later look like particle self-interactions, loops, or mass corrections?

Do not promote. Just animate and see if it teaches anything.

### Object 6 — the donut/mug equivalence crusher

Build pairs of worlds that look different externally but have the same internal observable graph.

World A: smooth torus.  
World B: lumpy coffee-mug embedding.  
World C: lumpy embedding plus same smooth internal metric.  
World D: lumpy embedding plus metric/coupling split.

Only World D is physically different to an inside observer.

Toy output:

- if all observables preserve the same relation graph, collapse worlds into one equivalence class;
- if one coupling sees a different distance rule, mark a fingerprint.

Purpose: prevent visual metaphors from pretending to be new physics unless a measurable relation changes.

### Object 7 — the shell that sees itself

A compact CMB toy:

- Generate random texture on a 3-torus fundamental cell.
- Observer samples a sphere of radius `eta`.
- Use modulo wrapping to sample the texture.
- When `eta > L/2`, self-overlap begins.
- Render sky map and explicitly mark duplicate pixels that sample the same fundamental-cell voxel.

Variants:

1. translation torus;
2. rectangular anisotropic torus;
3. twisted/screw torus;
4. Klein-style orientation flip;
5. multi-channel torus where light, gravity, and packet closure use different effective compact lengths.

This is the first code candidate.

## Tiny implementation sketch

Create `lightcone_donut.py` later with:

- `Topology` class: `wrap(point)`, `images(point, radius)`, `orientation_transform(path_class)`;
- `SkySampler` class: observer, sky directions, lookback radius, source field;
- `DuplicateDetector`: hashes wrapped source-cell coordinates and finds repeated sky pixels;
- `Channel` class: metric/length/orientation rules per phenomenon;
- output: PNG sky map, duplicate mask, matched-circle candidate list, JSON run packet.

First run can be deliberately crude:

- 2D torus first;
- observer at `(0.37Lx, 0.41Ly)`;
- random scalar field on fundamental square;
- circular lightfront samples;
- duplicate coloring by wrapped coordinate.

If the 2D version teaches anything, lift to 3D sky projection.

## Failure is welcome

This playground should fail loudly and usefully.

A toy is worth keeping if it creates:

- a new visualization;
- a new variable name that clarifies thinking;
- a new equivalence/fingerprint distinction;
- a solver interface idea;
- a negative result;
- a surprising analogy that points to a better formal question.

A toy should be thrown out if it only renames existing ideas, fits arbitrary thresholds to desired behavior, or produces beauty with no reproducible object behind it.
