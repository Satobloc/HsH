## Result

No existing durable machine-readable autotag/Nathan-Direct surface located in the inspected generation chain records the exact scanned source commit.

The root Nathan Direct manifest records generator path and package/count metadata, but no `source_commit`, workflow run identity, generation timestamp, generator commit/blob identity, publication-base commit, or output hashes. The Stage-2 manifest records its upstream path/count and queue counts, but likewise no source-snapshot identity. `indexes/autotag/` contains the summary, conversation tag index, conversation-tag manifest, and user-message tag index; there is no separate root run manifest. The visible autotag summary records corpus/count diagnostics, not source SHA. Repository code search did not surface a retained `source_commit` field elsewhere in this chain.

The workflow itself confirms why the distinction matters: generation occurs from the initial `main` checkout, while publication later fetches and hard-resets to the latest `origin/main` before re-laying the previously validated generated snapshot. Therefore publication ancestry cannot safely be substituted for scanned-source ancestry.

This closes the bounded search requested by Run 52: the missing artifact-local lineage is not already supplied by an obvious adjacent retained manifest in the inspected chain.
