## Result

Run 97 established from implementation that `context_each_side` is selected by timestamp-sorted list adjacency rather than conversation-graph ancestry. Run 98 sampled one exercised LAB1 window and found it graph-local. This run found a concrete positive counterexample in another retained LAB1 extraction.

In `2026-09-15-LAB1-AFTER-015519.json`, the first selected rows include:

1. assistant `06f138ff-3c3b-470b-a74f-a3c0cd2e30de`, parent `ee668a69-b132-442a-9380-c4fb7251185a`
2. user target `1a875034-ddd0-48c3-af1e-4c77af02ef0f`, parent `01a81054-432e-4ac4-a8ca-fb0b3b9c4eb0`
3. assistant `c95d429b-b1e6-4a86-92f2-5c63f5e24fc4`, parent `1a875034-ddd0-48c3-af1e-4c77af02ef0f`

The extraction request has `context_each_side: 1`. The preceding selected assistant is therefore chronological context for the user target, but it is **not** that user's recorded parent. The following assistant is graph-local because it records the target as its parent.

This is the first retained-output positive sample confirming the Run-97 risk: at least one generated extraction contains a context row selected from outside the target's immediate parent/child graph relation.

A second visible sequence in the same extraction reinforces the presence of branching: user `f45f2791-1fd0-4ffe-af29-76d6d4962a7c` and earlier user `1a875034-ddd0-48c3-af1e-4c77af02ef0f` both record parent `01a81054-432e-4ac4-a8ca-fb0b3b9c4eb0`, while their respective assistant children are separate. This makes timestamp adjacency particularly unsafe as a synonym for branch context.

## What this establishes / does not establish

**Established:** the extraction implementation's chronological-context semantics have produced at least one retained cross-branch/immediate-ancestry mismatch in an exercised `context_each_side: 1` output. The risk is no longer merely theoretical.

**Not established:** the total prevalence across this extraction or the extraction corpus; whether the non-parent preceding row is on some more distant shared ancestral branch; whether downstream Nathan Words use materially depended on that context row; or whether any substantive interpretation was changed by it.

The right classification is an extraction-context provenance defect/risk, not source corruption. Original conversation graph identity remains preserved in each selected row's `parent` field, making deterministic detection and repair feasible.

## Archive / infrastructure implication

A deterministic validator should classify each context row relative to each target using graph identity, rather than treating list adjacency as sufficient. Minimum useful classes remain: immediate parent/child-local; same-branch but non-immediate; cross-branch; unresolved. The extractor itself should eventually distinguish `chronological_context_each_side` from graph/branch context, or implement an explicit graph-local mode, rather than silently calling chronological neighbors context.

This is a bounded interface/semantics finding. I did not modify shared extraction machinery or Nathan Words workflow ownership.
