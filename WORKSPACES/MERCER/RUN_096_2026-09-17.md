## Findings
### HsH source tree: reconstructable by generated commit parent
The workflow's commit loop does, in order:
1. `git fetch origin main`;
2. `git reset --hard origin/main`;
3. reset the checked-out GLASS repository to its then-current `origin/main`;
4. rerun external discovery and the resolved Viewer builder;
5. stage only generated Viewer data/curated outputs and the two date manifests;
6. create one `[skip conversation-viewer] Refresh Viewer data, GLASS discovery and manifests` commit and push it.

The latest sampled generated commit is `3ad949f15c8eb4fcffa0c9708c009a17cf79bfe9`; its sole parent is `a4d909d9d5dbc1aa92e4875814f59f48864117ec`.

Under the workflow's own transaction, that parent is therefore the HsH `main` state from which the successful attempt rebuilt the generated outputs, except that the workflow itself may rewrite the generated date manifests during the build before committing them. The canonical HsH conversation/source files and builder/configuration inputs are reconstructable at the parent commit. This is substantially stronger historical reproducibility than the runtime Viewer behavior alone suggests.

### Generated outputs: committed snapshot
The generated commit itself freezes `CONVERSATION_VIEWER/data/conversations.json`, discovered-external metadata, curated derivatives, and the date manifests at the successful build transaction. Thus the catalog artifact and its HsH input tree can be paired historically as generated commit -> parent commit.

### GLASS source tree: not equivalently frozen by the HsH commit
The workflow resets the external GLASS checkout to then-current `origin/main`, but the inspected workflow does not record that checkout's repository commit SHA into the HsH generated commit or a build manifest. Structurally discovered external records carry per-source content hashes, which can establish individual-byte identity where present, but Runs 90–92 established that the sole current manual registration (Srena) is not hash-enriched. Therefore the HsH parent relation does **not** by itself reconstruct the exact complete external repository tree scanned.

## Classification
The Viewer has three distinct reproducibility/currentness layers:
- **runtime rendering:** live canonical bytes fetched from mutable URLs (Run 95);
- **historical HsH build:** generated commit is strongly pairable to its HsH parent source tree under the inspected workflow;
- **historical external build:** weaker; external checkout commit is not recorded, although structurally discovered files have individual hashes and the current manual Srena record does not.

This is a provenance/reproducibility distinction, not evidence of a current catalog/source mismatch, source error, or theory correctness.
