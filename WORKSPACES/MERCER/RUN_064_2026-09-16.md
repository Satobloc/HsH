## Finding 1 — ChatGPT Voice Glitch residue is tightly localized
The two same-message-ID-set comparisons represented by the SAT_CONVOS_7 copy/copies against the SAT_CONVOS_8 copy have:
- 2,413 shared mapping nodes;
- zero side-only nodes;
- zero topology-changed nodes;
- exactly one changed shared node;
- exactly one changed `message.content` node;
- the only reported differing node-local path is `message.content.parts`;
- zero normalized visible-text changes;
- zero visible-text-comparable changed nodes for that changed content.

Thus the unresolved difference is not broad export churn. It is a single `parts`-carrier payload difference that the deliberately narrow ordinary-text projection cannot interpret. Do not classify it as text-equivalent or semantically equivalent.

## Finding 2 — v3 comparability counter has a naming/denominator defect
Inspection of `mapping_diff_signature()` shows `visible_text_comparable_nodes` is incremented for every changed shared node for which both sides yield a visible-text hash, regardless of whether `message.content` changed. Consequently the emitted field name `visible_text_comparable_changed_nodes` does **not** mean “content-changed nodes whose changed content is text-comparable.” This explains the Run-63 `AI Enclosure Critique` result of 344 text-comparable changed/shared nodes despite only 54 content-changed nodes.

This does not invalidate `visible_text_changed_nodes`: differing visible-text hashes still establish normalized ordinary-text divergence. It does make the comparability denominator misleading and should be repaired before using that count as an equivalence-rate statistic.

## Recommended repair contract
Keep existing fields for backward auditability if desired, but add an unambiguous content-scoped counter such as `content_changed_visible_text_comparable_nodes`, incremented only inside `if content_changed` when both visible hashes are non-null. Optionally add `content_changed_visible_text_uncomparable_nodes`. Version the report schema when changing field semantics rather than silently redefining an existing field.

For the Voice Glitch residue, add a privacy-preserving structural carrier signature (types/keys/list lengths and hashes only; no body values) for content-changed but text-uncomparable nodes. This should identify whether the differing `parts` payload is an attachment/audio/multimodal/object carrier without retaining its content.
