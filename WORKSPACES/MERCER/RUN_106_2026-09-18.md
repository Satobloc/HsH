## Bounded operation

The pending whole-corpus classifier execution could not be completed from the available repository connector because the raw source conversations required by the classifier cannot be materialized as a checkout through the available execution route. Rather than manufacture prevalence figures, this run took the separately queued provenance bite: determine whether retained bounded extraction products persist the exact HsH source tree/ref from which they were generated.

## Finding

They do not.

`extract_raw_window.py` copies the request object into each retained payload and records `source_title`, `conversation_id`, selected message rows, selected-user count, and the next user timestamp. It does **not** record repository commit SHA, branch/ref, source blob SHA, script blob/version, workflow run identity, or generated artifact hash.

`.github/workflows/extract-raw-window.yml` checks out moving `main` (`actions/checkout@v4`, `ref: main`, `fetch-depth: 0`), runs every request, and commits changed extraction outputs. It does not persist `git rev-parse HEAD` or equivalent source-tree identity before extraction. It also pushes directly after the extraction commit without a fetch/rebase/reset reconciliation step.

The retained RUSSIA sample confirms the payload-level side: its `request.source_path` is preserved, but no immutable repository/tree identity accompanies that path.

## What this establishes

Historical extraction **path provenance exists**, but historical extraction **repository-state provenance is incomplete**. A retained output can identify the declared raw source path and message-level ancestry fields, but the payload alone cannot establish which exact version of that raw source file or extractor implementation generated it.

This is provenance/observability debt, not evidence that any retained extraction is stale, corrupt, or semantically wrong. It is independent of the graph-context defect-risk measured in Runs 97–105.

The workflow also falls short of the current cross-repo execution standard's stronger unattended-write expectations: exact source refs should be recorded, and publish should reconcile against current target state before pushing. No workflow change was made locally because workflow redesign/ownership belongs with Sable/systems review.
