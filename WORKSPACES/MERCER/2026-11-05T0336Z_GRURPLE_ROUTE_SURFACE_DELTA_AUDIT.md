## 4. New workflow improvement: two-stage, route-surface delta classifier

The existing Meridian PDF-first re-entry contract correctly says not to retry merely because another hourly turn arrived. This run makes its trigger test more discriminating by separating **source/renderer invalidation** from **permission to perform a live route readback**.

| Event class | Evidence required | Correct consequence | Does it authorize a live route probe? |
|---|---|---|---|
| Source invalidation | Accepted/reviewed A or B source blob changes | Re-run source/feed binding; rebuild the derivative from the new pinned source | **No**, not until a matching derivative is deployed or previewed |
| Feed/route invalidation | A/B feed entry, route ID or source-to-route binding changes | Reconcile route mapping and source identity; rebuild as required | **No**, not by itself |
| Renderer/build invalidation | Format adapter, parser, semantic-IR, renderer/config, dependency lock or build manifest changes | Rebuild the derivative from the exact pinned source and record new digests | **No**, not until deployed or previewed |
| Deployment observation trigger | Retrievable deployment manifest identifies the A/B route and exact derivative digest, or an owner preview supplies URL plus deployment identity | Perform one bounded readback per affected route | **Yes** |
| Authenticated readback capability | Current browser context is listable, authenticated as required, and can reach the exact target origin | Perform one read-only readback; infer no write permission | **Yes, read-only** |
| Policy-only change | Presentation Gate or Reader Routing Registry changes | Recompute the acceptance checklist and identify any new build requirements | **No**, unless accompanied by a deployed route change |
| Non-trigger | Unrelated main commit, `generated/discovery.json` refresh, Viewer-only/Whirligig-only deployment, repository feed staging alone, or old `site_version`/`posted_date` metadata | Preserve current pending state; do not spend another route-probe attempt | **No** |

This is a two-stage gate:

1. **Invalidate/rebuild stage:** source, feed, adapter, renderer or build changes make some part of the evidence chain stale. They require source-binding and derivative work, not a blind live-route probe.
2. **Observe stage:** a deployment or authenticated preview must bind the exact A/B derivative to an identifiable route. Only then is one live readback useful and authorized.
