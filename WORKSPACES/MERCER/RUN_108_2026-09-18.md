## Finding
The production extractor uses `int(req.get('context_each_side', 1))`: when a request omits `context_each_side`, the extraction radius is **1**. The Run-105 classifier instead used `int(req.get("context_each_side", 0))`. Therefore any retained extraction whose request relied on the extractor default would have been silently classified by the audit tool as `skipped_no_positive_context`, understating positive-context file/window coverage.

This is a classifier fidelity defect, not evidence of a defect in any historical extraction output. It also does not establish that any retained request actually omitted the field; that population question remains execution/data dependent.

## Change
Updated `WORKSPACES/MERCER/classify_extraction_context_graph.py` so omitted `context_each_side` defaults to `1`, exactly matching `extract_raw_window.py`. Added a local comment documenting why this default must stay synchronized. Commit: `101ebcb0f5bb772a4793a741e7711a5ca273ca79`.
