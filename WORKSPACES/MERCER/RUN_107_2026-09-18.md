### A. Retained extraction provenance: minimum additive fields

For future `WORKSPACES/COMMON/extraction_outputs/*.json` payloads, add a top-level provenance object (name is implementation-owner choice) recording at generation time:

- `run_id`: unique workflow/job identity;
- `source_repository`: `Satobloc/HsH` for the current extractor;
- `source_commit`: exact checked-out HsH commit (`git rev-parse HEAD` before generation);
- `source_path`: retain the existing request path;
- `source_blob_sha`: immutable blob identity for the declared raw source at `source_commit`;
- `extractor_path`: `WORKSPACES/COMMON/scripts/extract_raw_window.py`;
- `extractor_blob_sha`: immutable blob identity for the extractor at `source_commit`;
- `request_path` and/or request blob SHA when the request is retained as a repository artifact;
- `generated_artifact_sha256`: content hash of the generated JSON (or a sidecar/manifest hash if self-hashing would be circular).

The existing request/conversation/message/parent fields remain useful and should not be replaced. This patch adds immutable execution/source identity; it does not rewrite historical outputs.

### B. Workflow checkout/run observability

In `.github/workflows/extract-raw-window.yml`, capture the resolved checkout SHA immediately after checkout and pass it into the extractor or retained run manifest. Do not use `main`/`latest` as the retained source identity. If practical, expose the GitHub workflow run ID/attempt as `run_id` while retaining the repository commit separately.

### C. Publication safety

Before committing/pushing generated extraction outputs:

1. fetch the current target branch;
2. reconcile/rebase onto current `origin/main` (or regenerate against the fresh base if that is the safer generated-output policy);
3. rerun validations whose assumptions could have changed;
4. push without force;
5. on rejection/collision, fetch and retry non-destructively or stop.

Add workflow concurrency protection if overlapping extractor jobs can target the same generated namespace, while retaining fresh-base protection as the actual integrity mechanism.

### D. Acceptance checks

A patched run should establish, by named checks only:

- every new retained JSON identifies an exact HsH commit;
- declared `source_path` exists at that commit and its recorded blob SHA matches;
- extractor blob SHA resolves to the script used at that commit;
- run identity is present;
- generated-output hash/manifest verifies after generation;
- historical extraction outputs are unchanged;
- publication is from a fresh/reconciled base and no force push is used.

These checks establish reproducibility/provenance and publication discipline only. They do not establish semantic correctness of extraction context or theory/model correctness.
