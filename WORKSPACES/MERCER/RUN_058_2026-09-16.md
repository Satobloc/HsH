## QA interpretation
Raw `conversation_id` should remain an identity/provenance grouping key, not a suppression key. The next diagnostic increment should expose **mapping-internal difference signatures** for shared message IDs: counts of changed shared nodes; whether `message.content` differs; whether parent/children topology differs; and compact differing JSON-path counts/examples without copying message bodies. That would separate harmless export metadata churn from content-bearing or graph-bearing divergence while preserving privacy and keeping the diagnostic reporting-only.

A locally syntax-checked v2 design was prepared during this run but not published because it has not yet been exercised against the repository checkout. No untested diagnostic replacement was committed.
