## 4. Substantive architecture improvement: two orthogonal type ladders

The important correction is to keep **carrier/current type** separate from **timesheet-intersection type**. They answer different questions and must not be collapsed into a single “rank” or “worldtube dimension.”

### A. Carrier and current representation

In a 4D ambient space, the archive's candidate carrier types must remain distinct:

| Carrier/support | Geometric dimension | Tangent-current component rank | Poincare-dual form degree |
|---|---:|---:|---:|
| centerline / worldline γ¹ | 1 | 1 | 3 |
| worldsheet ᵂ² | 2 | 2 | 2 |
| boundary shell ∂W³ | 3 | 3 | 1 |
| full-core region W⁴ | 4 | 4 | 0 |

The tangent-current and Poincare-dual columns are **different encodings**. A rank-three object can therefore mean a tangent 3-current supported on a 3D shell, or a 3-form Poincare dual supported on a 1D worldline. Component rank alone does not identify support dimension.

A one-parameter sweep of a 1D curve can produce a 2D worldsheet only if an independent second tangent direction and a valid sweep/immersion are supplied. Its Poincare-dual degree then changes from 3 to 2. This is not Hodge duality: in 4D, Hodge degree sends 3 to 1. A current-level push-forward/sweep map, its domain, regularity and boundary/conservation conditions remain to be specified.

The 1-index (J_μ) in the SAT4D draft is described in the current audit as an averaged flux/linking-density current, with a separate Dirac-bilinear use and no explicit map between them. Do not silently identify it with the Poincare dual of a shell or bulk.

### B. Timesheet intersection

The second ladder concerns a 3D resolving sheet Σ³_t in (M^4):

| Object intersected with Σ³_t | Readout type | Status |
|---|---|---|
| 1D centerline γ¹ | point-like intersection | conditional on transversality |
| 2D worldsheet W² | 1D trace | conditional on transversality |
| 3D boundary shell ∂W³ | 2D rim | conditional on transversality |
| 4D full-core region W⁴ | 3D mouth/section | matches the Nathan Direct 4D/3D distinction; boundary regularity still matters |

This exposes an ambiguity that should be removed from future prose: **“worldtube” must be typed as either a full-core region (W^4) or its 3D shell ∂W³.** If the word means the shell, its intersection with a 3D timesheet is a 2D surface; if it means the full-core region, the observed section is 3D. These are not competing descriptions of one same-dimensional object.

The optional 2D normal-plane/circle support in Nadir's restricted construction is a separate selected subobject. It is not the full 3D mouth, and no inclusion/projection/selection map from it to the full core has been established.

The reusable architecture should expose separate embeddings and pullbacks:

- (i_W: W^4 hookrightarrow M^4): full-core inclusion, only when the region interpretation is intended.
- (i_Σ: Σ_t^3 hookrightarrow M^4): resolving-sheet inclusion.
