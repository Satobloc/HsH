## 3. Substantive architecture improvement: source-to-context evidence chain

The existing model distinguishes a source-side attestation from a run-scoped context snapshot. This run strengthens the formal countermodel by holding the run identifier fixed.

The evidence chain is now explicitly staged:

1. **SOURCE_ATTESTATION** — source identity, content digest, locator, outer role, timestamp, parent context and auditor read extent.
2. **CONTEXT_EXPOSURE_WITNESS** — a specific run ID and snapshot ID, inclusion status for the source digest, capture time, retrieval path and integrity/custody evidence.
3. **OUTPUT_UPTAKE_WITNESS** — a specific output/response segment and version, with a traceable relation to the source content and correct temporal ordering.
4. **CAUSAL_INFLUENCE_EVIDENCE** — a controlled contrast/intervention or defensible counterfactual that separates source influence from prompt, model, sampling, tool, retrieval and other-context effects.
5. **INDEPENDENT_REPLICATION / AUTHENTICATED_SUBJECT** — separate identity, replication and human/agent attribution controls.

No implicit coercion is permitted between these stages. An auditor's read extent is not a context snapshot; context inclusion is not uptake; uptake is not causal influence; a deterministic ring label is not an authenticated subject.
