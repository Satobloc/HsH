## 3. New evidence distinction

Nadir's published witness firewall (#1618) correctly separates preimage/range witnesses, connector group elements, source attestations, measurement witnesses and execution witnesses.

Its `SOURCE_ATTESTATION` record includes source identity, digest/locator, outer role, timestamp, parent context and actual read extent. That source-side read extent must not be silently interpreted as proof that a specific model execution included the source in its context.

I recommend preserving the following as distinct typed records:

| Record | What it can establish | What it cannot establish alone |
|---|---|---|
| `SOURCE_ATTESTATION` | Stable source identity, content digest, locator, outer role, timestamp, parent and coverage/read-extent metadata | Inclusion in a particular execution context |
| `AUDIT_READ_EVENT` | Which auditor/runtime retrieved which exact source range, when and by which method | Historical model exposure |
| `CONTEXT_EXPOSURE_WITNESS` | A specific run/context snapshot included an exact source/message/span, with ordering and capture provenance | Causal influence on an output |
| `OUTPUT_UPTAKE_WITNESS` | A specific output references or uses a source span | That the source caused the output |
| `CAUSAL_INFLUENCE_EVIDENCE` | A bounded intervention/contrast linking exposure changes to measured outcome changes | General mechanism outside the tested conditions |
| `AUTHENTICATED_SUBJECT` | Independently supported subject/instance identity | Message exposure or causal uptake |

These are not a mandatory linear pipeline. Each relationship needs its own explicit map, provenance, conditions and epistemic status. In particular, an auditor's read of a file is not a context manifest, a populated conversation pointer is not an exposure manifest, and an output's self-report is not a causal intervention.

For a usable `CONTEXT_EXPOSURE_WITNESS`, the minimum candidate fields are run ID, model/product/version when known, context snapshot identifier and digest, exact source/message identity, exact included span or byte/line range, ordering, capture method, and observation timestamp. Missing historical context snapshots remain UNKNOWN, not ABSENT.
