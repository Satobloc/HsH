## 4. Explicit cross-prototype composition map

The Switchboard and Threading prototypes are sibling state models, not demonstrated layers of one system. The existing Lean modules provide several useful partial projections, but there is no source-defined common identity key or composition adapter joining them.

The proposed common key is:

\[
K=(eventId, leaseId, threadId, seedVersion, candidateFreezeId, attemptId)
\]

The records to be joined are:

- **S: SourceRunWitness**: repository, exact source commit and blob, harness, command, environment, exit status, stdout/stderr digests, assertion manifest, execution scope, and K.
- **T: ThreadState**: thread ID, parent goal, seed version, return condition, author state, vacate time, receipts, and displaced work.
- **R: OutputReceipt**: K, worker label, optional authenticated subject ID, artifact path and digest, outcome, source-run-witness ID, and exposure-manifest ID.
- **P: PublisherEvidence**: submission ID, opened-event ID, opened payload digest, publisher run ID, outcome, artifact digest, and independent artifact-readback digest.
- **D: DeliveryEvidence**: target thread ID, artifact digest, delivery state, and explicit acknowledgment ID.
- **I: IdentityEvidence**: authenticated subject identity when actually available.
- **X: ExposureManifest**: source and message ancestry, with retrieved, prompt-included, delivered, and acknowledged events kept distinct.

The core composition is a partial pullback over K:

\[
\mathcal E_{core}=S\times_K T\times_K R
\]

Publisher and delivery evidence attach only on their own shared keys:

\[
\mathcal E_{pub}=\mathcal E_{core}\times_{(eventId,artifactDigest)}P
\]

\[
\mathcal E_{delivery}=\mathcal E_{core}\times_{(threadId,artifactDigest)}D
\]

Identity and exposure remain separate projections:

\[
\mathcal E_{independence}=\mathcal E_{core}\times I\times X
\]

These are proposed typed joins, not source-defined types or a claim that the current prototypes already implement them. A composition is undefined when required keys are absent or disagree; missing values are not filled by worker labels, filenames, timestamps, or nearby context.

### Required composition conditions

1. Thread IDs must match across Switchboard context, ThreadState, receipt, and delivery target.
2. Seed versions must match across ThreadState and receipt.
3. Every candidate check must bind to the same immutable candidate-freeze ID.
4. Event, lease, and attempt identities must bind the exact execution and source-run witness.
5. The source-run witness must identify the exact source commit/blob and harness/command, not merely a successful workflow label.
6. Artifact digests must agree across receipt, publisher readback, and delivery evidence.
7. Publisher success does not imply recipient delivery. Delivery does not imply acknowledgment.
8. Worker-label diversity does not imply authenticated-subject diversity.
9. Distinct authenticated subjects do not imply independent source exposure. That requires complete exposure manifests with disjoint source ancestry and no cross-exposure before the relevant freeze.
10. Formal proof, source execution, publisher readback, historical chat delivery, and physical/observational validation remain distinct evidence axes.

### Current source and formalization gaps

The Python Threading OutputReceipt contains worker, artifact, seed_version, outcome, timestamp, and metadata. It does not contain thread ID, event ID, lease ID, attempt ID, candidate-freeze ID, artifact digest, source-run-witness ID, authenticated subject, or exposure manifest. ThreadState.add_receipt checks seed_version but not thread ID. This is why the current receipt projection cannot uniquely attach a receipt to a thread.

The Python Switchboard passes an untyped event dictionary. Its Hydra loop fingerprint is narrower than the proposed K and omits event, lease, thread, seed, candidate-freeze, and attempt identity.
