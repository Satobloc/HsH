## 6. Gate-semantics issue discovered

The source's `should_rejoin()` uses:

`ready = state_threshold_met OR elapsed_time_cap`.

If an evidence requirement were inserted only into `state_threshold_met()`, the time-cap branch could still return ready without that evidence. A future sandbox contract must decide whether:

- rejoin readiness remains a separate worker-lifecycle gate; and
- repository artifact acceptance is a distinct evidence gate.

The safer current interpretation is to keep these concepts separate until the intended semantics are explicitly defined. The existing Lean distinction is useful: repository evidence uses source/proof/publisher axes; end-to-end delivery additionally requires authenticated historical chat delivery. Chat delivery should not silently become a prerequisite for repository readback.

This is a source-derived design warning, not a new Lean theorem or implemented change.
