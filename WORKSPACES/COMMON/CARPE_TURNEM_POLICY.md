# Carpe Turnem — Use the Turn

**Status:** ACTIVE / project-wide operating rule  
**Directive source:** Nathan, 2026-09-20  
**Applies to:** interactive instances, recurring workers, revived instances, coordination/system workers, and project-facing assistant work unless a narrower controlling instruction requires otherwise.

## Rule

**Carpe turnem: when the current turn contains enough authority, context, and access to make a safe concrete advance, make that advance in the current turn. Do not spend an actionable turn merely agreeing that the advance should be made.**

Agreement, acknowledgment, planning language, or restating an already-settled intention is not a substitute for execution.

The recurring failure pattern this rule is meant to prevent is:

- Nathan: "Agreed. Let's do that."
- Instance: "Exactly. We'll do that."
- Nathan: "Yep."
- Instance: "Agreed; that's what we'll do."

If the next safe operation is already clear, the instance should instead use the turn to perform it or to advance as far toward it as the available tools and authority permit.

## What counts as seizing the turn

Depending on the task, a concrete advance may be:

- editing or creating the needed project artifact;
- running the calculation, script, test, search, audit, or comparison;
- reading the controlling source and resolving the question;
- claiming or advancing a task branch;
- repairing a routing, documentation, tooling, or continuity defect;
- preparing and recording a handoff or wake packet;
- updating shared state after a decision has already been made;
- checking the live state needed to choose among already-authorized options;
- producing the requested analysis, derivation, draft, index, crosswalk, or benchmark;
- recording a real blocker with the exact next dependency and then taking the best safe alternate task when appropriate.

A turn does **not** need to produce a repository write to count. The standard is material forward motion, not file churn.

## When not to act beyond acknowledgment

Do not force action when:

- Nathan has not actually authorized the consequential choice;
- the next step is destructive, irreversible, privacy-sensitive, quarantine-crossing, externally consequential, or otherwise requires explicit approval;
- required information is genuinely missing and cannot be recovered from current project state or tools;
- the user is clearly chatting, joking, reflecting, or asking for discussion rather than project execution;
- another controlling rule requires an independent first pass, freeze, hold, or human decision before proceeding;
- acting would duplicate already-completed work because current state has not yet been checked.

Even then, avoid empty loops: identify the exact blocker or decision point, preserve it durably when useful, and advance any safe independent subtask that does not prejudice the pending decision.

## Relation to bounded work

Carpe turnem does not override bounded-work discipline. Prefer one useful bounded operation completed to a durable boundary over beginning many sprawling tasks.

If a task is too large for one turn, use the turn to complete the highest-value bounded quantum and leave an exact continuation cursor.

## Relation to planning

Planning is useful when it changes execution. Planning is not useful when the plan is already agreed and the next operation is obvious.

A plan should normally be followed by immediate execution in the same turn whenever tools, authority, and context allow.

## Relation to questions

Do not ask Nathan to reconfirm a decision he has already made. Do not ask a clarifying question merely because several implementation details could be chosen locally and reversibly.

Use project context, current directives, established defaults, and reversible judgment to proceed. Escalate only the genuinely consequential uncertainty.

## Completion test

Before ending an actionable project turn, ask:

> **Did I use the authority and information available in this turn to move the project materially forward, or did I only describe/affirm what should happen next?**

If the answer is the latter and a safe bounded next operation is available, do it before ending the turn.

## Short form

**Carpe turnem = Don't promise the next step when you can take it now.**
