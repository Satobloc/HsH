## Executive assessment

The workshop has become substantially better at preserving provenance, preventing assistant-to-user attribution drift, separating formal proof from empirical truth, and leaving durable handoffs. The October 29 graviton/gluon source-role audit and Aster's October 30 correction are a concrete example: a question was not allowed to become an asserted identity, and a prior-context quotation was not allowed to masquerade as a raw archival message.

But the central scientific bottleneck has not moved at the same rate as the control architecture. The repository contains many carefully specified workflows, source notes, specialist lanes, branch artifacts and candidate geometries. The decisive missing object remains a **source-faithful, operational H(s)H forward model** that maps a minimally specified physical configuration to a named observable, with constraints tight enough to generate a risky prediction rather than a post-hoc interpretation.

This is the main distinction between an active research workshop and a demonstrated physical theory. The former is now extensive. The latter still requires a small number of explicit, independently testable maps.

## Where the system is still leaking effort

### A. Control-plane growth is outpacing scientific closure

The live documents are detailed and mutually reinforcing, but there is a risk that each new directive, role, receipt and handoff becomes another layer to maintain. Five hourly leases can create a high volume of artifacts without guaranteeing convergence on a shared physical deliverable. The metric should not be number of runs, notes, proofs or branches. It should be reduction in uncertainty about a named model and its observable consequences.

**Recommendation:** Every substantive artifact should identify one parent research question, one current blocker, one acceptance test, and one next action. If it cannot change a model definition, constrain a parameter, validate a source, eliminate a hypothesis, or improve a paper gate, it should be short or deferred.

### B. The geometry is still under-typed at the physical interface

The recovered source supports a four-dimensional ambient history and a three-dimensional resolving timesheet, with filaments and gravitational interaction described in that setting. The later finite-core/worldtube language is a plausible extension, but its physical status must be disaggregated:

- **Source-supported core:** 4D history/carrier; 3D timesheet/slice; filament histories and intersections/interactions.
- **Candidate representation:** a worldtube as a finite cross-section swept along a history.
- **Not yet forced by the recovered source alone:** a particular core radius law, material framing, twist constitutive law, contact potential, Kelvin-vortex medium, or a unique timesheet response equation.
- **Required interface:** a specified projection/intersection/readout map from the 4D configuration to a measured 3D/2D/1D observable.

This distinction is not cosmetic. Every optional constitutive choice adds flexibility. Unless it is fixed independently or penalized, it can absorb discrepancies and destroy falsifiability.

### C. Cross-scale identity remains a missing-map problem

The July source does not establish that a gluon is a graviton at another frequency or scale. It records Nathan's question, followed by an assistant's categorical answer. The required scale/composition map and observable readouts remain unspecified. The same discipline applies to proposed equivalences with GR, string theory, QCD, information geometry or climbing-rope mechanics: resemblance is a hypothesis generator, not a derivation.

### D. Formal verification needs to target the model's bottlenecks

The universal Lean rule is valuable, but repeated easy lemmas about abstract separation, factorization or bookkeeping can create a false sense of mathematical progress. The highest-value formal targets are conditional statements about:
- whether the proposed projection/readout is well-defined under stated regularity assumptions;
- which geometric degrees of freedom are identifiable from a given observable family;
- whether two distinct internal configurations necessarily produce the same measured output;
- which constraints eliminate that degeneracy;
- whether a claimed limit reproduces the established standard model.

A proof should expose a real structural constraint or impossibility, not merely encode a convenient definition. No new Lean theorem is claimed by this panorama.

## The highest-value architecture change

Create and maintain one compact **Model-to-Observable Contract** as the common interface between archive, geometry, formalization and empirical work. It should be a table, not another sprawling charter.

| Layer | Required declaration | Current status |
|---|---|---|
| Source object | Exact Nathan Direct passages and historical equation versions | Partly recovered; Oct 29 raw exports still missing |
| State/configuration | Ambient space, timesheet, filament/worldtube, allowed degrees of freedom | Partly specified; finite-core constitutive content unresolved |
| Dynamics | Action/equations/constraints and boundary conditions | Not yet a single source-faithful closed system |

| Parameters | Shared, calibrated, fixed, nuisance and optional parameters | Not yet frozen as one common register |
| Observable | Named quantity, units, estimator, dataset and uncertainty | Several candidates exist; no complete common H(s)H prediction contract |

The contract should have one canonical version and be linked from each worker's artifact. Do not create a new tool until existing repository, Lean CI, Math Hopper, Whirligig and research integrations have been checked for an adequate implementation.

## Paper campaign reality check

- **P1, Nov 9:** LLM cognition and shared-source errors. The paper must distinguish genuine administered model experiments from synthetic/stipulated demonstrations. If real experiments cannot be run and documented, narrow the claim to a methods/analysis paper rather than implying empirical model behavior.
- **P2, Nov 30:** actual measured physical system. This is blocked until a common H(s)H forward map can produce an independently scoreable observable. A standard comparator, nuisance treatment and holdout protocol must be fixed before evaluating agreement.
- **P3, Dec 14:** full-theory manuscript. It must distinguish recovered source, historical conjecture, current reconstruction, proved mathematics, empirical support and unresolved postulates. A coherent narrative is not a substitute for closure.

These are separate gates: source/attribution, mathematical verification, empirical evidence, independent review, and readable LaTeX/PDF. Passing one does not imply passing the others.

## Immediate priorities, in order

1. **Do not spend another cycle rephrasing the October 29 source correction.** The correction is saved on issue #996 and in Aster's note. Recover raw exports if available; otherwise retain the explicit provenance limitation.
2. **Choose one minimal physical observable and one real dataset.** Do not begin with the most elaborate worldtube ontology. Start with the simplest source-supported geometry that can be mapped to an existing measurement. If the model cannot yet specify the forward map, record the precise missing constitutive/kinematic choices and stop short of fitting.
3. **Separate forced geometry from optional physics.** For each added feature (finite thickness, twist, contact, Kelvin response, soliton), state whether it follows from Nathan's source, standard physics, a mathematical convenience, or a new physical postulate. Require a distinct observable consequence for each postulate.
4. **Make identifiability a first-class test.** Ask what observations could distinguish internal thickness/twist/contact from a thin-filament or standard-theory description. If multiple internal configurations have identical readouts, identify the equivalence class and the extra measurement needed to split it.
5. **Use Lean where it bites.** Formalize a source-faithful projection, a genuine identifiability/no-go result, or a standard-limit condition. Do not pad the proof ledger with unrelated generic lemmas.
6. **Protect specialist ownership and reduce duplicate traffic.** Route each artifact to one primary owner and one reviewer. The next run should consume the existing handoff, not recreate it.
