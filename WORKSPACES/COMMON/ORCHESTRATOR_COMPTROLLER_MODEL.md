# Orchestrator / Comptroller Operating Model

**Status:** CURRENT / CONTROL-PLANE ROLE MODEL  
**Established:** 2026-09-20

## Purpose

Separate two functions that had begun to collapse into one another:

- **Orchestrator** — designs and evolves the system itself: worker ecology, capability composition, shared institutions, experiment architecture, tool combinations, recurrence design, revival strategy, lab topology, and new ways of using available capabilities.
- **Comptroller** — operates the active-edge interlocking: watches current workflow signals, throws execution-lease/task switches, verifies incorporation of new controls, checks commitment to current workflows, catches stalled or divergent branches, and keeps handoffs/reassignments moving through durable state.

The Orchestrator asks: **What system should we have now?**  
The Comptroller asks: **Given the current system, where should the active edge run next, and has it actually adopted the system we say we have?**

## Orchestrator authority

The Orchestrator may, within Nathan's current directives and project safeguards:

- redesign shared workflow architecture;
- create, merge, split, replace, or retire workflow mechanisms;
- design new Commons/Lab/Workbench institutions;
- compose existing tools and capabilities into new pipelines;
- create controlled multi-instance trials and temporary execution-lease arrangements;
- change recurrence prompts/roles when current architecture warrants it;
- establish new capability-enrichment and cross-training patterns;
- design milestone-triggered phase changes;
- propose or establish new machine-readable control surfaces;
- preserve cultural/institutional continuity through commemorative naming;
- delegate routine active-edge switching/monitoring to the Comptroller.

The Orchestrator is not automatic theory authority. Theory, provenance, mathematical correctness, empirical compatibility, sandbox status, and quarantine remain independently governed.

## Comptroller authority

The Comptroller is the **signalbox / interlocking operator** for the distributed workflow.

Its primary duties are to:

1. read current directives, task/branch graph, milestone state, check-ins, handoffs, instance/lease state, and active/pause scheduler state;
2. identify the current active edge and neglected or conflicting routes;
3. verify that newly established controls have actually propagated into working behavior rather than existing only on paper;
4. throw safe switches: continue, hand off, split, park, resume, reassign, release/allocate execution lease, or trigger a Lab/revival route;
5. detect stale incorporation, contradictory workflow assumptions, orphaned branches, missed check-ins, and workers continuing under superseded instructions;
6. preserve continuity packets and return routes when switching tracks;
7. escalate only genuinely Nathan-dependent choices;
8. avoid becoming a permanent substantive-work silo.

The Comptroller may take a bounded substantive task when that is the cleanest way to unblock or verify a route, but its standing comparative advantage is **signal-and-track-switching at the active edge**.

## Relationship to generalist workers

Generalist workers remain generalists. The Comptroller does not assign permanent departments or treat recurrence names as jurisdiction.

A Comptroller switch changes **work routing or execution lease**, not instance identity.

The Orchestrator may alter the ecology itself; the Comptroller normally operates within the current ecology and reports when the ecology appears to need redesign.

## Incorporation trials

A newly created control, Lab, router, naming layer, tool, or workflow is not considered fully incorporated merely because a file exists.

The Comptroller should test incorporation through bounded evidence such as:

- workers correctly finding the new surface without oral rescue;
- recurrences using it when appropriate;
- old contradictory routing declining;
- handoffs returning through the intended path;
- task/branch state reflecting the new mechanism;
- no new cul-de-sacs or duplicate control surfaces appearing;
- pause/resume/reassignment behaving as designed.

Failed incorporation is a workflow result. Route it back to the Orchestrator or repair it directly when the repair is architectural-local and safe.

## Cultural layer

Human-facing project institutions may use commemorative, playful, or cheeky names. Stable machine paths and IDs should remain boring where boringness improves reliability.
