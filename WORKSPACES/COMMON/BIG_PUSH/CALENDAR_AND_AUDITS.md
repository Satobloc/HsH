# THE BIG PUSH — Calendar and Audit Cadence

This is a cadence map, not a prediction of completion dates. Phase order and evidence gates remain in PROJECT_CONTROL.md. The :00 heartbeat trigger is designed but currently unarmed because the platform rejected the task-prompt update.

## Standing triggers

| Trigger | Action | Owner |
|---|---|---|
| Every interactive Big Push session | Refresh INTERACTIVE_HEARTBEAT.md; re-read active tray and exact cursor | Current interactive operator |
| Every :00 hourly recurrence, once the prompt overlay is installed | Check heartbeat/state; if heartbeat age is at least 36 hours, resume one bounded operation; otherwise do not compete with a fresh interactive session | Existing :00 continuity steward |
| Every completed operation | Update queue, source/read ledger, receipt, next cursor, and any affected project control | Operator completing the unit |
| Every 5 completed operations or phase gate | Conduct scope, evidence, parked-drawer, repetition, and process-efficiency review | Current operator; :00 steward only when automation is active |
| Weekly while the programme is active | Review phase status, risks, calendar, capability gaps, and whether the boot/protocol still fit actual work | Current operator |
| Every 14 days while active | Check archive coverage, stale source assumptions, missing repositories, and neglected work packages | Current operator |
| Before any phase is closed | Verify exit evidence, completeness, provenance, unresolved contradictions, and independent review where appropriate | Current operator |
| Before context exhaustion or a handoff | Create a succession packet and verify every referenced artifact and cursor | Current operator |

## Programme gates

1. **Historical recovery:** archive inventory and sequential primary-source reading.
2. **Workflow reconstruction:** complete schematic of intentions, controls, tools, handoffs, outputs, failures, and revisions.
3. **Resource assay:** all three repositories and relevant connected/local/remote capabilities, distinguishing listed from tested.
4. **External orientation:** sourced research map and explicit relation to SAT/H(s)H questions.
5. **Strategic debt audit:** old goals, plans, and unimplemented proposals reconciled.
6. **Architecture competition:** two or three substantively different designs, evaluated against the recovered requirements and tested capabilities.
7. **Decision and charter:** user-reviewed institutional direction, implementation stages, costs, risks, and rollback.
8. **Build and evaluation:** incremental deployment with measurable outcomes and scheduled pruning.

## Review questions

- What has the programme promised to recover that remains untouched?
- Which source families, repositories, or tools are underrepresented?
- Are we confusing a summary, a search hit, or a repeated mirrored artifact with independent evidence?
- Has an old plan been silently displaced rather than dispositioned?
- Is the active tray still one bounded operation?
- What can be automated safely, and what still needs explicit human judgment?
- Which procedure has become repetitive or ceremonial and can be simplified?
- What new resource or method would materially change the capability assessment?
- What should be parked, reopened, pruned, or retired?

## Missed-cycle fallback

If one or more scheduled cycles are missed, do not fabricate work or backfill imaginary receipts. On the next run, inspect the last verified queue and artifact state, identify the first incomplete operation, and resume from its exact cursor. If the state is contradictory, stop advancement and reconcile before writing.
