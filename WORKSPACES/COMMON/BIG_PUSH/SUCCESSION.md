# THE BIG PUSH — Succession and Context-Limit Protocol

## Purpose

Carry project intent and exact work state across finite ChatGPT context windows without pretending that a new activation is the same continuous instance.

## Before context exhaustion

1. Refresh INTERACTIVE_HEARTBEAT.md.
2. Reconcile PROJECT_CONTROL.md and WORK_QUEUE.md.
3. Record the exact active source path, blob SHA, read range, and next cursor.
4. Separate sources fully read, partly read, searched, indexed, and not yet examined.
5. Record decisions, unresolved questions, competing interpretations, blockers, and parked items.
6. Verify every new repository artifact by independent readback; record commit and blob SHA.
7. Preserve the complete conversation export when available, with checksum and verified storage status. Never claim export/upload/readback without evidence.
8. Write a concise successor note that names the single first action.

## Successor startup

1. Read BEDROCK, current steering/onboarding, and required campaign controls.
2. Read BOOT.md and the current control, queue, protocol, calendar, heartbeat, and automation state.
3. Read the named primary source range from the exact cursor; do not rely solely on a predecessor's summary.
4. Verify current repository versions and scheduler state before modifying anything.
5. Continue one bounded operation. Do not redesign the institution or broaden scope merely because a new context began.

## Handoff packet minimum fields

- project purpose and top priority;
- current phase and gate;
- one active operation and exact cursor;
- primary source identity and blob SHA;
- work actually completed versus searched or merely planned;
- repository tree/branch and relevant artifact SHAs;
- current task IDs and confirmed schedule/enabled status, if relevant;
- Mersearch request lane status and restrictions;
- current blockers and uncertainty;
- next action and stop condition;
- any new procedures tested, rejected, or recommended to other workers.

## Improvement loop

After each substantial phase, assess whether the boot capsule, protocol, resource pointers, tool instructions, and successor packet are still fit for purpose. Revise only when evidence shows a useful improvement. Keep BOOT.md small; move detail into the appropriate reference document.
