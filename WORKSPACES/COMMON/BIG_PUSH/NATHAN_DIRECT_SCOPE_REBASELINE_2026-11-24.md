The Big Push is **not** a mandate to reconstruct or literally rebuild the entirety of historical SAT/H(s)H workflow designs, nor to complete a comprehensive history of every prior workflow proposal before useful work can proceed.

Its historical-recovery purpose is selective and methodological: study, recover, compare, and learn from the strongest relevant exemplars, especially:

- SAT-O;
- Activator Modes and related mode systems;
- Back Hallways;
- Star-Shaped Derivation Map;

Recover enough original context to understand the intended method, how it was used, what outputs it produced, what failed or remained incomplete, and which parts are reusable now. Do not turn exemplar study into an end in itself. Historical breadth is justified when it resolves a concrete design question, a source conflict, a dependency, or a consequential missing method.

## 3. Capsule / Credenza information architecture

Apply the experimental **Key → Memory Credenza → Castle** model to navigational tools and documentation work premises, informed by the successful features and observed experiments of the existing capsule implementation:

- **Key:** tiny role/remit/current-position launch capsule.
- **Credenza:** compact navigational/control surface with routes, triggers, statuses, and return cues.
- **Castle:** authoritative repository, source, project, tool, and evidence environment.

Treat the Credenza as a model for navigation, not a duplicate archive. Use small access cards and modular pointers. Load deep instructions only when a trigger makes them relevant. Apply this to Big Push navigation and, where appropriate, to documentation and navigation work premises across the active portfolio.

This is a rolling-reconfiguration and improvement model, not a one-time architecture decree. Trial the smallest useful configuration in real work; record whether it improves orientation, rediscovery, continuity, execution, and recovery; track overhead, duplication, stale pointers, missed work, and drift; then retain, revise, split, combine, or retire compartments based on observed results. Keep configuration-first and reversible. Do not create new automations, alter protected schedules, or silently change project ownership.
