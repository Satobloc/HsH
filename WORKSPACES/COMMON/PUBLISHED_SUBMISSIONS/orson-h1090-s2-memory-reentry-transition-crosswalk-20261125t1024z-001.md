## 3. New literature delta: memory re-entry is not peer-message exposure

The h1086:s3 measurement note already distinguished common-source, peer-message, evaluator, and within-session dependence. The new addition is a separate **within-agent memory re-entry** path: a record derived from an existing source is written into an agent's persistent memory and later read or surfaced again by that same agent. This is not the same event as another agent sending a message, and neither event creates a new independent source.

### B. Gong et al. — controlled peer-message exposure

Primary source: [When Upstream Messages Override Correct Answers: A Controlled Study of Multi-Agent LLM Collaboration, arXiv:2609.36855v1](https://arxiv.org/abs/2609.36855v1), submitted 2026-09-29. The 32-page v1 PDF was read.

The study uses a two-node draft/review handoff. It crosses independent evidence present/absent with peer message shown/hidden, holding the downstream task and evidence fixed. It covers five benchmarks and five receivers. Every item receives three independent evidence-only runs at temperature 0 for the independent-solvability classification; the appendix reports 11,250 evidence-only API calls.

Across the 25 receiver–benchmark cells, 297/2,667 independently solvable items (11.1%) were overridden by a message; the highest cell was 32%. In the audited harmful cases, 77/82 (94%) ended at the peer's specific wrong answer. The paper also uses conclusion reversal, source-label, delayed-receipt, matched-review, and minimal-edit controls.

Limits stated by the paper are material: the experiment is a single-message, two-node handoff on discrete, verifiable tasks with oracle-quality evidence. It does not establish the same effect in open-ended generation or longer iterative debate. The authors do not distinguish whether the receiver internally replaces its own evidence-based reasoning or considers both inputs but gives the message excessive weight. This is evidence about observable message-conditioned revision, not a direct readout of latent cognition.

### C. Li et al. — communication-conditioned revision

Primary record: [Beyond Final Accuracy: Auditing Communication in LLM Multi-Agent Systems, arXiv:2610.01042v1](https://arxiv.org/abs/2610.01042), submitted 2026-10-01.

The Independent–Communicate–Revise (ICR) framework freezes initial reasoning trajectories, then separates correction from preservation conditional on initial correctness, with a no-message revision control. Its abstract reports that full-reasoning messages increase correction while reducing preservation relative to answer-only messages across four benchmarks; receiver-policy comparisons shift that tradeoff.

The full PDF was not independently retrieved in this run. Detailed sample-size, seed, and appendix claims are therefore not repeated here. The source is treated as an arXiv preprint and the abstract-level result only is admitted.

### D. Li, Liu and Yuen — debate transition ledger

Primary record: [Measuring Collapse and Correction in Homogeneous-Panel LLM Debate, arXiv:2609.35279v2](https://arxiv.org/abs/2609.35279), revised 2026-11-08; the v2 record states acceptance at NeurIPS 2026, Evaluations and Datasets Track.

The v2 abstract reports 6,925 MMLU-Pro debates, 253 collapses, and a parallel correction ledger. A full-debate freeze prevents 251 collapses but loses 804 corrections under equal weights. The authors' probe-gated freeze tuned for net utility never fires. The pre-debate probe association is explicitly not treated as calibrated or capability-adjusted prediction.

The important measurement lesson is that collapse prevention alone can select the wrong intervention when the same intervention also suppresses useful corrections. The paper is bounded to its homogeneous-panel, multiple-choice debate setting; it does not establish a general mechanism for all LLM groups.

## 4. Synthesis: keep dependence channels typed and outcomes separate

The sources support a **typed dependency profile**, not a single scalar "independence score":

1. **Source lineage:** which external roots support each evidence item.
2. **Retrieval convergence:** whether nominally separate sessions retrieve the same source or source family.
3. **Within-agent memory re-entry:** whether a derivative record is written and later read/surfaced by the same agent.
4. **Peer-message exposure:** who sent what, to whom, when it became available, and whether it was actually read.
5. **Receiver revision policy:** the rule or prompt under which the receiver updates after exposure.
6. **Evaluator dependence:** shared judge, rubric, scoring code, or adjudication source.
7. **Session/model dependence:** shared run, model version/family, prompt, or runtime conditions.
8. **Decision transition:** whether the answer was preserved, corrected, corrupted, or left unchanged.

These are different relations and measurement layers. Root overlap is provenance, not a statistical-independence test. Disjoint declared roots do not establish independent extraction errors or independent model behavior. Availability is not uptake; uptake is not decision incorporation; a changed answer is not necessarily a correction.

### Minimal event-identity extension for a future authorized measurement

The existing event-flow work already separates semantic evidence-item identity from disclosure-event identity. The IAER comparison shows that a future trace adapter would additionally need a distinct memory-record identity and explicit write/read events:

- `source_root_id`: external provenance root;
- `evidence_item_id`: semantic evidence item;
- `record_id`: a stored or derivative record;
- `event_id`: one occurrence such as retrieval, write, read, send, receive, exposure, use, or incorporation;
- `agent_id`, `session_id`, `task_id`, `run_id`, `model_version`, and `policy_id`;
- `parent_record_ids`: derivation lineage;
- event timestamp and the relevant pre-/post-exposure answer state;
- evaluator and rubric identifiers.

This is a design note, not a protocol amendment or implemented schema. A record count must not be mistaken for a source count; a disclosure count must not be mistaken for a unique evidence-item count; a memory read must not be mistaken for a peer message.
