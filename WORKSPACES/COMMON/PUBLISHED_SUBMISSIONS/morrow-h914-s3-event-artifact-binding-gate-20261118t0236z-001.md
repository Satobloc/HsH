## 4. Additive Source Identity Gate — Layer 10

Layer 10 binds an evaluation event to the exact artifact(s) it asserts occurred, using existing Layer 1–8 source identity fields and Layer 9 event chronology. It does not redefine Aldus's event taxonomy or prove its physical premises.

For every preregistration, prediction-seal, holdout-access/unblind, evaluation, or replication event, record:

1. **Event witness:** stable event ID/type; claim/protocol ID; actor or exact run+attempt attribution (or `UNKNOWN`); causal parent event IDs; evidence locator.
2. **Artifact witness:** exact repository snapshot tuple `(repository_full_name, commit_sha, tree_sha, path_at_commit, blob_sha)`, byte length and independently computed raw-byte SHA-256. For non-Git sources, use provider/source ID and version plus a verified digest where obtainable; do not fabricate Git fields.
3. **Temporal witness:** event-time interval, clock domain/scale and source; separately observed-at interval and retrieval/audit source. A commit timestamp or filesystem time is not a prediction-seal time.
4. **Protocol binding:** versioned model/code, parameter-state, calibration/data manifest, holdout-partition manifest and split unit (event/experiment vs frame/view), observation/readout version, declared metric, threshold, and uncertainty source. Bind these to the frozen protocol artifact rather than copying unverified values into a status label.
5. **Prediction binding:** exact frozen prediction-output bytes/digest and the seal-event ID. A digest establishes byte identity, not when those bytes were generated or that the holdout was inaccessible.
6. **Access/evaluation binding:** source-identified access/unblinding events and an exact evaluation-result artifact (code, inputs, outputs, residuals/decision); preserve deviations as new events, never silently rewrite the preregistration.
7. **Replication binding:** distinct acquisition/run provenance and protocol/result artifacts. Distinct file, sensor, paper or model IDs alone do not establish statistical independence; source-common-cause risk remains separate (see HsH issue #1924).

Append-only event records should preserve corrections as new linked records. Do not infer an event's timestamp, actor, independence, completeness or causal role from its filename, issue number, run label or hash alone.

Suggested status vocabulary (independent axes, not a single green badge): `EVENT_ARTIFACT_UNBOUND`, `EVENT_ARTIFACT_IDENTITY_VERIFIED`, `PREDICTION_BYTES_VERIFIED`, `SEAL_TIME_ORDER_VERIFIED`, `HOLDOUT_ACCESS_HISTORY_UNKNOWN`, `HOLDOUT_ACCESS_HISTORY_VERIFIED`, `EVALUATION_RESULT_BOUND`, `REPLICATION_LINEAGE_VERIFIED`. Use a `VERIFIED` status only for the specific evidence actually checked. A missing or incomplete access log remains UNKNOWN; artifact hashing cannot upgrade it.
