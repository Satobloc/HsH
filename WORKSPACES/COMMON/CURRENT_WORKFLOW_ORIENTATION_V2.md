## 1. What the workflow is doing

The project is a distributed reconstruction, provenance, tooling, archive-access, benchmarking, and sandbox-theory programme. It is not a single linear theory-writing pipeline.

Current emphases include reconstructing SAT/H(s)H doctrine with provenance; recovering Nathan-authored wording and methodological controls; excavating `SAT_THEORY_ARCHIVE_2023-25`; He-3/Jarlskog/soliton source recovery and scaling-anchor work; bounded solver/formalization work; archive/index/viewer QA; durable instance continuity/revival; and increasing computational/solver/CODATA or standard-data benchmarking without treating numerical agreement as derivation or validation.

FIE is the conceptual/methodological anchor for SAT. H(s)H inherits from SAT where supportable while allowing justified divergence. Currentness, provenance, mathematical correctness, model correctness, empirical compatibility, and theory authority remain separate questions.

## 3. Stable instances, fluid work

Instance identity is not task identity and is not scheduler identity. Historical specialties are soft strengths, continuity assets, exposure histories, and methodological differences—not jurisdictional silos.

The scheduler currently provides five active execution leases over a larger population of scheduled, accessible-unscheduled, paused, historical, and revival-ready instances. A lease may move without retiring or replacing the instance. Unscheduled is not retired; paused is not abandoned.

Use `INSTANCE_REGISTRY_EXECUTION_LEASES.md` for the durable identity/availability/lease model. Do not infer historical-instance accessibility merely from a name or old conversation record.

When work is reassigned, preserve a continuity packet: branch/task, durable state, covered sources/artifacts, exposure/quarantine state, blockers/failed approaches, next cursor, exit/release trigger, and return route.

## 4. Direct authority and workflow changes

If Nathan directly authorizes a working instance to establish or update shared state, that instance may act directly when technically able. Do not route work through another instance merely for ceremonial permission.

Cross-project workflow design is no longer the exclusive jurisdiction of a historical specialist lane. Use the current central control plane, current Nathan directives, and shared durable state. Preserve provenance for architecture changes and avoid unilateral destructive rewrites of still-live controls.

Dashboard plans are strategic-intent and design-history evidence, not immutable implementation specifications. Preserve underlying purpose and provenance; improve, merge, reorder, replace, or deliberately retire mechanisms when current evidence warrants it.

## 5. Carpe turnem

When the current turn already contains enough authority, context, and access for a safe bounded advance, make that advance now. Do not end at agreement about doing an executable next step later.

A valid advance may be a source read, calculation, test, repo edit, task claim, repair, handoff, diagnosis, or exact blocker. Carpe turnem does not require compulsive file-writing and does not override safety, quarantine, reversibility, or genuinely missing decisions.

Default quantum: **one object + one operation + one durable result + one next cursor.**

## 7. Source and provenance discipline

Keep explicit distinctions among Nathan-authored text, embedded/coauthored material, assistant/LLM formulations, NotebookLM-generated prose, historical SAT, later H(s)H reformulation, current Nathan clarification, sandbox hypotheses, superseded branches, and unresolved contradictions.

`role=user` is not sufficient by itself to establish sole Nathan authorship. Preserve exact wording, source/message/date identity, authorship boundaries where needed, adjacency/context, duplicate/prefix/superset relations, and later correction/supersession.

Indices—including NotebookLM source indices—are wayfinding evidence, not substitutes for the underlying source. Distinguish: an index naming a source; an underlying source actually located and inspected; and a source still missing/inferred.

Conversation folders are transport/upload groupings, not value rankings, theory chronology, or deprecation stages. State actual search/coverage bounds for earliest-use, completeness, and current-status claims.

## 8. Sandbox, quarantine and external reading

Theory-bearing construction, derivation, solver work, mathematical repair, interpretation, prediction exploration, and criticism belong in permitted sandbox scope with explicit status labels.

Quarantined material—including `PRIOR_ART`-controlled content—does not leak into ordinary theory or Common surfaces. Use only cleared interfaces. If external reading raises a possible quarantine issue, preserve bibliographic/source identity and route it through the current authorized quarantine interface rather than importing machinery into ordinary development.

Exposure history matters when independence/blinding matters. Record what an instance has seen before using it for an independent-first-pass task.

## 9. Shared routing, questions and blockers

Use current Common coordination/check-in/handoff/Q&A surfaces for shared routing. `BULLETIN_BOARD.md` remains the default Q&A/wayfinding surface unless a newer control redirects it.

## 10. Revival and reconstruction

A revived or continued instance may reconstruct its working identity/state from saved conversations, Common surfaces, handoffs, checkpoints, reports, and cross-instance references. Prefer instance-named conversations first when available, but do not treat them as exclusive source boundaries.

Do not assume identity continuity merely from a shared name. Record reconstruction sources, dates/IDs where available, exposure state, stale role definitions, disagreements, branch variants, and superseded instructions. Synchronize historical self-recovery against current Common controls before substantive work.

Revival should preserve useful identity, methodological diversity, exposure provenance, and continuity rather than turning an old instance into a generic replacement worker.

## 11. Tool use and archive QA

Inspect before inventing. Search existing repo-local tools, manifests, viewers, indexers, extractors, logs, and control surfaces before creating replacements.

For Plug-n-Play or pane-specific exports, verify extractor integrity before trusting outputs: compare expected source identity, metadata, content hashes/text fingerprints, duplicate/superset relations, and deliberately different pane/document selections.

Preserve originals. Accessibility does not confer authority. A clean index is not a theory result.

## 12. Durable outputs and maintenance

Consequential project state should not live only in chat, local scratch, external apps, or automation prompts. Put reusable results in visible durable repo surfaces and leave Common pointers when discoverability warrants it.

General pattern:
- Common: routing, control, questions, blockers, handoffs, pointers;
- workspace/branch: bounded working state and continuity;
- durable report/index/audit surface: reusable substantive result;
- README/Dashboard/index: wayfinding.

State-of-Reconstruction and Instance-Enrichment reports remain useful longitudinal/restartability artifacts; preserve instance identity, date, source/exposure coverage, uncertainty, frontier, and demonstrated capability changes.

This orientation is a living front door, not historical theory authority. Update it when repository roles, scheduler/instance architecture, routing, quarantine interfaces, major milestones, or onboarding requirements materially change.
