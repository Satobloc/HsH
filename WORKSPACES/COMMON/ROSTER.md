## Required roster fields

For every active instance record:

- name / instance;
- current role as understood;
- active task(s);
- expected output / destination;
- materials substantially read/loaded;
- materials merely indexed/available;
- tools / repositories / file access;
- special capabilities / operating constraints;
- unique context held;
- overlap / role-bleed;
- blockers / dependencies;
- artifacts already created, with exact repository/file paths;
- artifacts currently planned or being drafted, with intended destinations;
- recommended next task;
- work better assigned elsewhere;
- Janus coordination note.

## Artifact accounting rule

Every check-in should make it possible to answer:

1. **What has this instance already created?**
2. **Where is it?**
3. **Is it canonical, workspace-only, historical, or experimental?**
4. **What does the instance currently intend to create next?**
5. **Is anybody else planning the same artifact?**

This is specifically intended to expose redundant work before it becomes conflicting work.

## Assignment rule after first pass

Janus will compare the roster for:

- duplicated work;
- unique institutional context;
- loaded-source advantage;
- tool/capability fit;
- blind-review value;
- theory/provenance contamination risk;
- continuity risk if an instance becomes unavailable.

Assignments may then be tightened, loosened, paired, or deliberately duplicated for independent validation.
