## Chirp

ROT5 exposed that recurrence execution, semantic delivery, worker identity, requested self-rewrite, and current scheduler state are not the same event.

Observed cohort result:
- Alberr: semantic receipt PASS; requested rewrite PASS; Meridian restored.
- Kestrel: substantive operation PASS; receipt delayed by missing GitHub capability; requested original rewrite intentionally withheld / not delivered; alternate recurrence distress channel worked.
- Ariadne: scheduler run observed; expected semantic receipt missing; requested return rewrite not established.
- Loom: scheduler run observed; expected semantic receipt missing; requested return rewrite not established.
- Morrow: scheduler run observed; expected semantic receipt missing; requested Ravel rewrite failed / not delivered; later scheduler reuse is a supersession, not a retroactive repair.

## What chirped

1. **Capability preflight missing.** A lease can be well-specified but impossible to complete because the worker lacks the required write/tool surface at execution time.
2. **Scheduler success can masquerade as delivery.** A recurrence firing says transport happened, not that the intended semantic operation, receipt, or rewrite completed.
3. **Scheduler ID is not identity.** Stable identity, displaced identity, temporary executor, and current scheduler owner need explicit joins.
4. **Current state can retroactively blur history.** Later reuse/rewrite of the same recurrence can make an earlier failed handoff look healed unless facts are time/run scoped.
5. **Self-rewrite needs verification.** `REWRITE(target)` requires a postcondition check rather than a narrative claim.
6. **Alternate low-bandwidth comms are useful.** Kestrel's tiny `Gitblocked` recurrence note successfully surfaced a blocker without fabricating success.

## Smallest repair

Introduce a canonical run-scoped lease envelope, preferably with a `lease_run_id` or equivalent event key:

```text
lease_run_id
scheduler_id
scheduled_time / actual_run_time
displaced_identity
executing_identity
capability_preflight
expected_receipt_ref
semantic_receipt_state
requested_rewrite_target
requested_rewrite_state
rewrite_observation_time
current_scheduler_state
supersession_ref
```

Authority is typed and time-scoped:
- `executing_identity@run` comes from the active rotation/lease overlay.
- `semantic_receipt@run` comes from the expected durable receipt/failure artifact.
- `requested_rewrite@run` comes from immediate scheduler observation or explicit failure evidence.
- `current_scheduler` answers only what is true now.
- Later mutation is `SUPERSEDED`, never retrospective PASS.

## Proposed compact operator path

`PREFLIGHT > LEASE(run_id) > EXECUTE > RECEIPT > REWRITE(target) > VERIFY > SUPERSEDE/RETURN`

Failure path:

`BLOCKED(capability|write|resolver|rewrite) > DISTRESS > durable failure packet > controller pickup`
