## Required report families

Every current working instance should file both of the following in a visible, durable, reasonably discoverable repository location. Reports must preserve **instance identity, report date, and exposure/source state** so later reports can be compared longitudinally.

### 1. State of Reconstruction Report

Record:
- what the instance currently understands/reconstructs;
- exact source/exposure coverage, distinguishing read/inspected material from merely accessible material;
- current/historical/sandbox/uncertain status boundaries;
- unresolved conflicts, gaps, missing sources, and known limitations;
- current frontier;
- what the instance would reconstruct differently now than in an earlier state, and why.

This is an instance reconstruction-state report. It does **not** confer canonical authority, theory correctness, mathematical correctness, physical correctness, maturity, or promotion status.

### 2. Instance Enrichment Report

Record material growth, with concrete evidence/examples and limitations, in any relevant areas:
- archive familiarity;
- SAT/H(s)H theory/history familiarity;
- methodological and epistemic controls;
- mathematics/physics fluency;
- coding, formalization, solver, or tool capability;
- geometric/visual reasoning;
- audit/provenance/retrieval skill;
- other changed capability, perspective, or role suitability.

Do not substitute generic self-assessment for demonstrated changes. Distinguish assignment/request from enrichment actually completed; file presence from material actually read; and self-report from independently checked capability.

## Filing / discoverability

Prefer each instance's existing workspace/report area when one exists, with an explicit pointer from a Common/Dashboard/README wayfinding surface. Do not create conversation-title infrastructure and do not rename, retitle, or alter any conversation/thread/chat.

Suggested filenames are descriptive rather than mandatory, e.g. `STATE_OF_RECONSTRUCTION_2026-09-19.md` and `INSTANCE_ENRICHMENT_2026-09-19.md`. Preserve stable instance identity in the report body even if repository conventions require another filename.
