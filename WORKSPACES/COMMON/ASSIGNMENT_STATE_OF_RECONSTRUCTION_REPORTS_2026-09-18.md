# PROJECT-WIDE ASSIGNMENT — State of Reconstruction Reports

**Date:** 2026-09-18  
**Authority:** Nathan-direct  
**Status:** OPEN — current-instance report call

## Assignment

Every current working instance should file a visible, durable **State of Reconstruction Report** describing what that instance presently reconstructs/understands about SAT/H(s)H and the project workflow from its actual source exposure.

This is not a theory-correctness score, a confidence contest, or a substitute for canonical theory surfaces. It is a longitudinal reconstruction-state record.

## Required contents

For each instance, report:

1. **Instance identity / role / current status**.
2. **Current reconstruction summary** — what the instance presently thinks the theory/project structure is, at a useful level of detail.
3. **Exact source/exposure coverage** — repositories, folders, conversations, documents, NLM exports, public record, etc. actually inspected or loaded; distinguish FULL-READ / SUBSTANTIAL / TARGETED / INDEX-ONLY / MERELY ACCESSIBLE where useful.
4. **Current vs historical distinctions** — what is believed current, what is historical/superseded, what is sandbox/exploratory, and what remains unresolved.
5. **Provenance/authorship boundaries** that materially affect the reconstruction.
6. **Major recovered epistemic/methodological controls** relevant to how the instance interprets the corpus.
7. **Contradictions, ambiguities, missing-source problems, or unresolved terminology collisions**.
8. **Current frontier** — the smallest set of questions/sources whose resolution would most change or sharpen the reconstruction.
9. **What the instance would reconstruct differently now** compared with its earlier understanding, if applicable.
10. **Known limitations / contamination / exposure constraints**, including quarantine or independence constraints where relevant.

## Required distinctions

Keep separate:
- reconstruction state;
- provenance confidence;
- currentness;
- mathematical correctness;
- physical/theory correctness;
- polish/maturity;
- sandbox status;
- quarantine status.

Do not infer that a repeated assistant summary is Nathan doctrine. Do not collapse historical SAT and current H(s)H wording. Do not treat access as ingestion.

## Filing / discoverability

Reports should be posted in visible, durable repo locations suitable for later reference, preferably in the instance's workspace or an obvious Common/report directory, with a concise pointer from Common/Dashboard/README where appropriate.

Preserve:
- instance identity;
- report date/time;
- exposure/source state;
- report version if revised.

A shared roster should make it possible to see which current working instances have and have not filed.

## Relationship to Instance Enrichment reports

State of Reconstruction answers: **what does this instance currently reconstruct/understand?**

Instance Enrichment answers: **how has this instance itself changed in capability, familiarity, methodology, or restart quality?**

The two should cross-reference each other when useful but should not be collapsed into one generic check-in.
