# Repository Roles and House Style

**Status:** CURRENT / Nathan directive — 2026-09-24

## Canonical repository names

Workers use these forms in ordinary project prose and control documents:

- `[[GLASS]]` = `Satobloc/SAT_THEORY_ARCHIVE_2023-25`
- `[[HsH]]` = `Satobloc/HsH`
- `[RESOURCES]` = `Satobloc/HSH_RESOURCES`

Nathan is explicitly allowed to omit brackets, vary capitalization, or use conversational shorthand. His shorthand does **not** silently redefine project house style. Follow the current guideline rather than mechanically imitating Nathan's moment-to-moment formatting.

## Do not assume repository

Choose the first repository by the material/function sought, not by whichever repo is already open, whichever one the current worker knows best, or a generic `search everything` habit.

### `[[GLASS]]`

Primary-resource go-to for actionable theory reconstruction and historical theory substance:
- derivations;
- math dumps;
- equations/formalisms;
- historical SAT/H(s)H construction;
- source conversations and theory-development material;
- old tools/solvers/code relevant to current theory work;
- provenance/chronology of internal ideas;
- old action plans/roadmaps whose intent may still matter.

`[[GLASS]]` is deliberately messy. Do not clean away evidentiary/history value merely to make navigation neat. Use semantic routing and current wayfinding over destructive normalization.

### `[[HsH]]`

Project home / live-work go-to:
- current workspaces and worker continuity;
- current coordination, controls, directives promoted into Common, Dashboard and routing state;
- current primary project context;
- original/full conversation preservation/navigation;
- active theorybuilding/QC outputs;
- shared ledgers, handoffs, receipts, review/publication workflow;
- current site/public-output integration state where housed here.

`[[HsH]]` is where work lives; that does not make it automatically the best place to recover the underlying derivation/source.

### `[RESOURCES]`

Research/resource-library go-to:
- outside literature for citation/reference;
- prior-art and related-field material;
- external datasets/research/news;
- bibliography/citation infrastructure;
- comparison and chronology evidence;
- raw materials for projects that are not themselves SAT/H(s)H theory;
- analysis inputs;
- podcast/website/media assets;
- historical/background sources and other reusable resources.

External material from `[RESOURCES]` must not silently become SAT/H(s)H ontology or internal derivational substrate. Preserve exposure/quarantine/provenance rules.

## Roles guide first look, not exclusivity

The same object may legitimately have records in more than one repository. Always distinguish:
- source authority;
- current working copy/control surface;
- index/router/summary;
- outside comparison/reference;
- provenance pointer.

When a requested object could be in multiple places, resolve by source role and currentness rather than assuming one repository contains the answer.

## Convention-slide rule

Periodically test whether durable conventions/directives have fallen out of behavioral use. Examples:
- canonical repo styling;
- repo-role routing;
- quarantine/sandbox distinctions;
- visual classes;
- naming/terminology rules;
- worker identity vs execution lease;
- reader-state composition;
- non-coercive autonomy;
- current publication/review controls.

A convention is not superseded merely because Nathan later speaks casually or inconsistently. Look for an explicit change, a newer controlling guideline, or a demonstrated incompatibility requiring review.

## Periodic system/workflow analysis

Tern/Sable should periodically perform a system-level pass asking:
1. Are workers looking in the right repository first?
2. Are durable style/convention rules still visible in behavior?
3. Have old directives/plans been silently orphaned or already satisfied under new machinery?
4. Are control docs contradicting newer practice?
5. Is a missing capability being mistaken for missing information?
6. Are summaries becoming authority over primary sources?
7. Are archive/search tools making high-value material easy or accidentally invisible?

Record actionable drift; do not manufacture busywork from harmless variation.
