## 1. Core principle

A relationship is not promoted to a prediction merely because it reproduces a known number in one domain.

The predictive content appears when the **same relationship survives transport across multiple independently constrained domains without being refit, redefined, or fed the target back in**.

The object under test is the **relationship structure**, not any single fitted numerical value.

## 2. Derivation Loop

The historical process is revived in generalized form:

[
E
ightarrow
G
ightarrow
D_1,D_2,ldots,D_n
ightarrow
G'
ightarrow
E'
]

where:
- (E) is the starting relation/equation/constraint;
- (G) is its geometric/worldtube representation;
- (D_i) are independently constrained physical or mathematical domains;
- (G') is the reconstructed common geometry after transport;
- (E') is the relation recovered from the return path.

A successful loop requires more than (E'=E) algebraically. The return must survive **independent information barriers**. If the target or an algebraically equivalent quantity was supplied upstream, the loop is only a reconstruction/consistency check.

### Minimal loop requirements

1. Define the starting relationship exactly.
2. State all inputs and which are measured, derived, fixed by convention, or free.
3. Build the geometric/worldtube representation without importing the desired endpoint.
4. Transport the relationship into at least two materially different domains or representations.
5. Use domain-native constraints and measurements independently.
6. Return to the shared relation by a path that does not reuse the target.
7. Compare:
   - algebraic form,
   - dimensional structure,
   - invariants,
   - scaling exponents,
   - limiting behavior,
   - observable outputs.
8. Record closure failure just as prominently as closure.

## 3. Star-Shaped Derivation Map

The Star-Shaped Map is the multi-domain version of the loop.

A common hub (H) feeds independent spokes:

[
H ightarrow S_1,quad
H ightarrow S_2,quad
ldots,quad
H ightarrow S_n.
]

Each spoke must be independently constrained.

The useful question is not:

> Can one choose (H) to reproduce every spoke?

It is:

> Does one relationship at (H), fixed from a bounded subset of spokes, correctly propagate into held-out spokes without retuning?

### Predictive closure test

Partition spokes into anchors (A) and holdouts (V).

1. Determine the hub from (A) only.
2. Freeze all hub parameters and transformation rules.
3. Predict the values/relations on (V).
4. Rotate the held-out spoke and repeat.

This is **leave-one-spoke-out derivational closure**.

A relationship graduates from reconstruction toward prediction when it repeatedly survives this rotation.

## 4. What counts as prediction

### Reconstruction
A target quantity or algebraically equivalent information is used upstream and later recovered.

Example form:

[
x=f(hbar,ldots),qquad
hbar=g(x,ldots).
]

This is a consistency loop unless (x) is independently fixed.

### Relationship prediction
A structural relation is fixed in one domain and correctly determines a relation in another domain without target reuse.

Examples of legitimate prediction-bearing outputs include:
- exponent/scaling relations;
- dimensionless ratios;
- ordering/inequality relations;
- topological or geometric class constraints;
- mode-spacing relations;
- transformations that preserve an invariant;
- quantitative observables in held-out systems.

### Prediction set
The same frozen relationship succeeds across several independent spokes.

This is the intended SAT/H(s)H use of the Star-Shaped Map.

## 5. Current methodological upgrades

Every loop/spoke must now pass the following gates before predictive language is used.

### A. Provenance gate
Separate:
- recovered historical relation;
- Nathan Direct relation;
- assistant-generated reconstruction;
- standard-physics comparator;
- external prior art.

### B. Dimensional gate
No bare-number comparison across quantities with different dimensions.

### C. Coordinate-artifact gate
Apply BR-008:
- re-express singularities/discontinuities/invariants in coordinate-free or overlapping-chart form where possible;
- do not convert readout failure into physical structure.

### D. Identifiability gate
Ask whether different parameterizations produce the same observable.

If yes, the parameter is not independently identified.

### E. Independent-input gate
Do not count an output as predicted if the same quantity or algebraically equivalent information was used to construct the input geometry.

### F. Holdout gate
At least one spoke/domain must be genuinely held out from hub construction.

### G. Failure propagation
A failed spoke constrains or breaks the hub. Do not patch one spoke with a domain-specific correction unless the changed geometry/conditions are independently derived.

## 8. Relation to minimal-pair method

Minimal pairs are the local version of the Star Map.

A spoke should ideally compare systems that differ in one controlled variable or one clearly typed geometric condition.

Examples:
- (pp) vs (pn);
- (ppp) vs (ppn) vs (pnn);
- two-strand vs three-strand finite-core braid;
- same coarse worldtube, different internal morphology;
- same relation under particle, nuclear, and macroscopic realizations.

The purpose is to discover which relationship is actually invariant under scale/domain changes.
