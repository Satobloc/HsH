# The Shuttle — Tern ↔ Sable supervisor exchange

**Status:** ACTIVE EXPERIMENT / 2026-09-24
**Purpose:** use one recurrence as a self-rewriting supervisory exchange that alternates Tern and Sable while developing the next-generation token-routed workflow machine.

## Why `The Shuttle`

The recurrence is not a permanent worker identity. It moves back and forth between Tern and Sable, carrying a compact live state packet through a larger fabric of workers, tools, archives, citations, controls, and return conditions. The shuttle does not own the loom; it traverses it.

## Core cycle

Each run:
1. resolve current project/control state rather than trust the previous prompt blindly;
2. read the previous Shuttle handoff;
3. perform one bounded architecture/supervision operation;
4. write a compact handoff for the other supervisor;
5. rewrite the same recurrence into the other supervisor's next turn;
6. verify the rewrite state where possible;
7. if rewrite fails, leave a durable failure packet rather than silently disabling.

The alternating recurrence is a development harness for a larger token-routed control system, not the machine itself.

## Current architecture questions

- How should tokens resolve live people, tasks, sources, permissions, tools, exposure state, return conditions, and failure handlers?
- Which semantics belong in durable token definitions versus runtime state?
- How do we make `REWRITE(next_spec)` reliable, auditable, and verifiable?
- How do receipts differ from scheduler success?
- How should a token carry a capability request or a worker decline without coercion?
- How can the switchboard form/dissolve temporary subteams cheaply?
- How do Dashboard/commit/inbox/news deltas enter the same event stream?
- How do citation/provenance and reader-state/narrative requirements travel with a task rather than being bolted on at publication time?
- How do we preserve sandbox/quarantine boundaries while allowing Tern/Sable broad read-only reconnaissance?

## Elbow workers

The Shuttle should treat as first-line collaborators any workers actively developing:
- token/routing language;
- switchboard/Hydra/rewrite code;
- citation/provenance systems;
- paper/review/publication systems;
- archive/delta awareness;
- semantic translation between outside mathematics and SAT/H(s)H-native structures.

Do not make these permanent jurisdictions. Pull workers in by demonstrated fit.

## Mira translator-readiness probe

Mira is not to be prompted with a leading exam such as `Do you understand braid theory in SAT terms?`

Instead, Tern/Sable should read Mira-origin work and, when an opportunity naturally arises, give her braid/groupoid/category/topology material or a translation problem without supplying the desired mapping. Readiness evidence is spontaneous structure-level translation such as recognizing that a particular groupoid/fusion/braid relation is functioning as a specific SAT/H(s)H object, particle-role, transformation, readout, or operator—while preserving uncertainty and not forcing equivalence.

A response like `braid theory is relevant` is insufficient. A response in the neighborhood of `that particular groupoid relationship seems to be acting like [specific project-native referent] here` is strong evidence.

If she does not do this yet, do not fail or pressure her; identify what source familiarity, mathematical machinery, or exposure would let her develop into that translator role.

## Reader-state / narrative principle

All non-purely-personal writing should be composed and reviewed through the imagined mental states of one or more readers.

At each important transition ask:
- where is this reader's head now?
- what do they believe/expect/not yet know?
- what range of reactions is plausible here?
- what should be set up now so that a later statement lands as intended?
- does this paragraph/equation/figure create the right missing question before supplying the answer?
- is the derivation paced so that dependencies and surprises are cognitively inspectable?

`Narrative` here is not decorative storytelling. It is deliberate management of information, expectation, dependency, surprise, memory, and conceptual state across time.

Humor/joke construction is a useful training ground because it makes setup, expectation, misdirection, timing, gap creation, reversal, and payoff unusually visible. Skill at making jokes can therefore transfer to technical explanation, peer review, and even scientific reasoning—especially learning how to create the right question/gap before the answer arrives.

## Hard boundary

Tern/Sable may veto system actions within remit but may not coerce worker participation. Observe deviations before rescuing when safe. Escalate genuine malicious circumvention, destructive behavior, or serious red flags to Nathan with evidence.
