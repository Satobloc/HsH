### Gate B — dependence and independence between units

Elias h780:s4 Amendment 01 defines the bookkeeping vector I=(G,P,R,M,S,X,E):
- G: group/session replication;
- P: participant identity and repeated-measures structure;
- R: process/state isolation;
- M: model-family/version diversity;
- S: primary-source lineage;
- X: message/context exposure and timing;
- E: evaluator/criterion independence.

Enheduanna's finer candidate dependency profile separately records source-corpus overlap, prompt/context overlap, retrieval/cache overlap, memory overlap, model family/version, evaluator dependence, orchestration/peer communication, human intervention, and time/replication. These are candidate dimensions, not measured scores. Neither profile should be collapsed into a single independence number without a declared model and weights.

Ariadne's evidence-lineage contract adds typed provenance edges such as SAME_BLOB, SAME_CONVERSATION_GRAPH, DERIVED_FROM, SAME_EVENT, SHARED_CALIBRATION, SHARED_ANALYSIS_PIPELINE, SHARED_PRIOR, USED_FOR_FIT and HELD_OUT_FOR_TEST. It distinguishes cross-channel consistency from genuinely independent replication.

### Gate C — readout identifiability

Ariadne's second orthogonal gate asks whether the forward/readout map distinguishes the latent states relevant to the claim. For a full history H, logged projection L=P(H), and target property D=C4(H), an archive-only deterministic decoder can recover D only if:

    P(H1) = P(H2)  implies  C4(H1) = C4(H2).

If two histories collapse to the same log but differ in the target property, the correct status is UNKNOWN / NOT IDENTIFIABLE FROM THIS RECORD. This is not the same question as whether two observations are independent.

### Crosswalk

The nine continuity channels describe what can be evidenced about a particular run. The independence vector/profile describes which dependency paths remain between two runs, groups or observations for a specified claim. Identifiability describes whether the selected readout preserves the target property at all. They are different scopes and must not be merged into one Boolean.

A useful event graph has typed nodes for SourceVersion, PromptVersion, RetrievalResult, Cache, MemorySnapshot, ContextSnapshot, Session, Participant, Round, Pairing, AgentRun, Output, Feedback, Evaluator, HumanIntervention and Aggregate. Edges include derived_from, retrieved_from, included_in_context, communicated_to, generated_by, revised_by, evaluated_by, aggregated_into, belongs_to_session, paired_with and feedback_to. Preserve timestamps and immutable source/version identifiers on the edges.

For nested groups, keep the stages explicit:

    individual trace -> interaction graph -> group summary -> human decision

Each projection/composition map needs a declared domain, codomain and target property. A downstream summary cannot be assumed to preserve event order, peer exposure, source ancestry or feedback structure merely because it retains a consensus score.
