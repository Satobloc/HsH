## 3. Cross-boundary synthesis: same-freeze identity versus claim-specific transport

Two existing project pipelines share a **typed evidence-transport** structure, but they are not physically equivalent.

**P0 presentation chain**

`accepted manuscript blob -> renderer/build inputs -> presentation derivative -> deployment artifact -> reader route -> observed reader-facing content`

The accepted manuscript SHA identifies the source version. It does not prove that the renderer produced a faithful derivative, that the deployed route serves that derivative, or that a human reader can see the required equations/citations/provenance. The P0 acceptance gate therefore correctly requires actual reader-route inspection; a feed entry, source hash, build artifact, or repository commit alone is insufficient.

**P2 measured-system chain**

`physical state/history -> instrument and calibration map -> versioned measured dataset -> processed observable -> reconstructed geometric object -> candidate H(s)H claim`

Each arrow needs an explicit domain/codomain, support, version, calibration, nuisance parameters, uncertainty/covariance, and the claims it preserves. A processed dataset is not the physical system; a geometric reconstruction is not automatically identifiable from the instrument readout.

This is the right conditional test for asking whether a claim can be recovered from a readout.

The theorem does **not** prove that a particular rendering pipeline preserves scientific meaning, that a PIV projection is injective, or that an H(s)H physical map is true. Those require source-defined maps and observed evidence. No new theorem was justified because the relevant P0/P2 maps have not been instantiated in a source-complete form.
