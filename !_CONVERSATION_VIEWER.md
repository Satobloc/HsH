## ▶ One-click launch

### Windows checkout

Double-click:

**[`▶ LAUNCH CONVERSATION VIEWER.cmd`](%E2%96%B6%20LAUNCH%20CONVERSATION%20VIEWER.cmd)**

The launcher automatically chooses a free local port, starts the tiny static server from the repository root, and opens the Conversation Viewer in the default browser. No command line or port selection is required. Close the minimized launcher/server window when you want to stop it.

### GitHub / web launch

The viewer is already prepared for GitHub Pages. Once Pages is enabled for this repository with **Source: GitHub Actions**, run the existing **Deploy conversation viewer to GitHub Pages** workflow once. After that the hosted viewer itself becomes an ordinary one-click web link.

## Viewer features

- speaker-color conversation display
- progressive rendering for very large threads
- conversation browser and development/live filters
- within-thread keyword search with result list and timeline marks
- named research/provenance landmarks kept separate from source conversations
- message-position slider
- previous/next message and conversation navigation
- direct message addresses (`?c=<conversation>&m=<message>`)
- copyable provenance links
- speaker filters
- **Cruise** autoscroll
- **Message Replay**
- simulated **Typealong Replay** with adjustable speed
- keyboard navigation (`/`, `J`, `K`, `Space`)

## Manual local launch

If needed, from a checkout of the repository:

```bash
python -m http.server 8765
```

then open:

`http://127.0.0.1:8765/CONVERSATION_VIEWER/`

The page cannot fetch its data reliably when opened directly as `file://`; it needs an ordinary HTTP origin.

## Archive / provenance discipline

The viewer is a **derived interface**. It does not rewrite, normalize in place, move, deduplicate, or replace the raw conversation exports. The generated catalog points back to exact canonical source paths and the browser fetches the selected source JSON on demand.

The compact catalog is regenerated by `.github/workflows/build-conversation-viewer.yml` from the existing conversation-date manifests. The current implementation follows the active ChatGPT branch (`current_node` and parent chain) when available rather than flattening abandoned branches into the visible transcript.

## Landmark layer

Named conversation landmarks are kept separate from source conversations. See [`CONVERSATION_VIEWER/LANDMARKS.md`](CONVERSATION_VIEWER/LANDMARKS.md) for the annotation contract intended for points such as “first θ₄ formulation,” “worldtube transition,” “carrier bifurcation,” or other provenance-relevant moments.
